# 문풍 생성 SOP

> **로드 시점**: story-long-analyze Stage 6 실행 시. `분석보고.md`는 차단 수준의 선행 의존성이며, `장절/*_요약.md`, `장절/제1-3장_심층해제.md`, `원문/원문.txt`(또는 `.md`)는 품질 입력으로, 누락 시 아래 「실패 모드 및 다운그레이드」에 따라 항목별로 엄격하게 처리합니다.
>
> **출력**: `분석DB/{책명}/문체.md`(템플릿은 [style-profile-protocol.md](style-profile-protocol.md) 참조).

## 6단계 프로세스

### Step 1: 분석보고 핵심 필드 읽기

`분석DB/{책명}/분석보고.md`를 읽고 다음을 추출하세요:

- **「글쓰기 기법」섹션** → 문풍 「참고할 만한 기법」의 「글쓰기 기법 Top 5」를 채우는 데 사용
- **「참고할 만한 패턴」섹션** → 문풍 「참고할 만한 기법」의 「참고할 만한 패턴 Top 3」을 채우는 데 사용
- **「전체 책의 감정 리듬 개요 / 복선과 갈등 네트워크」섹션** → 문풍 「계층별 모방 제안」의 고급층과 적응층을 채우는 데 사용하며, 리듬과 수법만 추상화하고 구체적인 장면은 옮기지 않음
- **기본 정보**(제목, 주제, 총 장수) → 문풍 제목 및 「생성 기록」을 작성
- 「생성 기록」에는 저자가 이해할 수 있는 정보만 작성하세요: 참고한 자료, 샘플링으로 본 장, 생성 시간, 문체 사용 가능 여부 등이며, 파일 타임스탬프나 내부 강등 표기 같은 구현 용어는 기록하지 마세요.

### Step 2: 황금 3장 심화 분석

`chapter/제1장_심화분석.md`, `제2장_심화분석.md`, `제3장_심화분석.md`를 읽고 다음을 추출하세요:

- **개장 훅 유형 + 기법**
- **반응층 분석표**(대사 잠재의 샘플)
- **쾌감 배치 비율**（감정 교차 리듬 샘플）
- **참고할 요소**（Step 1과 병합하여 중복 제거, 「글쓰기 기법 Top 5」에 입력）

### Step 3: 장절 기조/주제 태그 시퀀스 추출

Grep으로 모든 `장절/*_요약.md` 읽기:

```bash
grep -hE '기조：(긴장|편안|슬픔|열혈|쾌감|달콤함|온화|공포|억압|기타)' 장절/*_요약.md
```

**주요 형식 주의사항**: `챕터/*_요약.md`의 실제 형식은 `주제태그X | 기조：Y`가 각 에피소드 포인트 다음에 별도 행으로 위치합니다(1장 10-40줄). `기조`는 **전각 콜론**을 사용하고, `주제태그` 뒤에는 **콜론을 붙이지 않으며**, 둘 다 **행의 처음에 오지 않습니다**. grep 패턴은 `^기조:` 같은 앵커를 사용할 수 없습니다.

**장 기조 집계 규칙**(장마다 하나의 장 기조, 문체 「감정 교대 모드」에 기록):

- 해당 장의 모든 에피소드 포인트의 「기조」 필드에서 최빈값 통계 수행
- 동수일 때(예: 5 긴장 vs 5 열혈) `_요약.md`에서 **가장 먼저 나타난** 기조를 선택(행 번호 기준)
- 출력 형식: `제N장: {장기조}`, 전체 책의 시퀀스로 연결

**장내 정서 기조 시퀀스**（「장내 기조 전환」분석에 사용）：

- 집계하지 않고 `_요약.md` 중 정서 기조점 출현 순서대로 유지
- 전환 빈도 통계에 사용：인접한 정서 기조점 기조가 다른 횟수 / 총 정서 기조점 수

### Step 4: 원문 샘플링

`원문/` 아래에는 **한 개의 전체 책 단일 파일만** `원문.txt`（또는 `.md`）**로 장 단위로 분할되지 않음**. 샘플링은 반드시 장절 구분 기호를 먼저 파악해야 함.

**올바른 Grep 패턴**：

```bash
grep -nE '^제[일이삼사오육칠팔구십백천양영0-9]+장' 원문/원문.txt
```

패턴은 한글 숫자(`제일장`) + 아라비아 숫자(`제1장`) + 천의 자리 수(`제일천영일장` / `제양천오백장`, 판롱/그릇된 비밀의 주인 수준의 장편 필수)를 포함하며, 행 시작에 고정하여 본문에서 언급된 오류 매칭을 방지합니다.

**Stage 0 장절 경계 하위 단계와의 관계**：이 하위 단계는 동일한 패턴으로 권위 있는 「장절 경계」표(`_progress.md`)를 생성합니다. Stage 6은 해당 표만 읽고 다시 슬라이싱하지 않습니다. 표가 누락되면 중단되고 Stage 0 진행 파일 재구성을 표시합니다.

**패턴이 일치하지 않는 경우**：

- Read를 사용해 전 100줄을 살펴보고 실제 장 제목 형식(예: `Chapter 1`, `권일 제일장`)을 확인한 후, regex를 그에 맞춰 조정하세요
- 극단적인 경우 장 분리 기호를 인식할 수 없으면 → 「생성 기록」에 `문체 사용 가능: 아니오: 장 분리 기호를 인식할 수 없음`이라고 작성하고 Step 4를 건너뛰세요. 다만 Step 1-3은 계속 진행할 수 있습니다

**샘플 슬라이싱**:

- grep의 `행번호:제N장` 목록을 얻은 후 제1장, 제10장, 제20장을 선택하세요(총 장 수가 20 미만이면 1/3, 2/3, 마지막 비율로 선택)
- 각 장마다 `Read offset={해당 장의 시작 행} limit=50`을 사용해 약 1000자를 잘라내세요
- 3개 단락을 `분해문고/{책이름}/_style-sample.txt`에 연결하여 저장하세요(이 파일명은 고정입니다. 변경하지 마세요). **첫 번째 단락은 `>`로 덮어쓰고, 나머지 두 단락은 `>>`로 추가하세요**. 전체 과정에서 `>>`를 사용하면 Stage 6을 다시 실행할 때 이전 라운드의 샘플이 누적되어 통계로 나온 문장 길이 분포가 두 라운드 혼합 결과가 됩니다.

**결정론적 문장 길이/구두점 통계**(주관적 「목측」 대체):

Stage 6은 **메인 스레드**에서 실행되며 Bash 도구를 사용할 수 있습니다. 이전 단계에서 준비한 `_style-sample.txt`를 다음 스크립트에 전달하세요(heredoc을 Python 소스로 사용하고, 샘플 경로는 argv로 전달하여 stdin heredoc과 `< file`의 이중 리다이렉션 충돌을 피하세요). 먼저 사용 가능한 인터프리터를 탐지한 후 실행하세요. **`python3`을 직접 사용하지 마세요**. Windows에서는 Microsoft Store 점유 프로그램이 트리거되어 exit 49 오류가 발생합니다.

샘플 경로는 **반드시 프로젝트 내 상대 경로**를 사용하세요. `/tmp/...`를 입력하지 마세요. 탐지된 인터프리터는 Windows 기본 python(`py` 런처)일 수 있으며, `/tmp/x.txt`를 `C:\tmp\x.txt`로 해석하여 Git Bash가 저장한 위치와 다른 파일이 되고, 스크립트는 FileNotFoundError를 직접 발생시킵니다.

```bash
SAMPLE="분해문고/{책이름}/_style-sample.txt"   # {책이름}을 실제 책 이름으로 바꾸세요. 점유 기호를 그대로 복사하지 마세요.
for PYBIN in python3 python py; do "$PYBIN" -c "" 2>/dev/null && break; done
"$PYBIN" - "$SAMPLE" <<'PYEOF'
import re
import sys
with open(sys.argv[1], 'r', encoding='utf-8') as f:
    text = f.read()
sents = [s for s in re.split(r'[。！？]+', text) if s.strip()]
total = max(len(sents), 1)
short = sum(1 for s in sents if len(s) < 15)
mid   = sum(1 for s in sents if 15 <= len(s) <= 30)
lng   = sum(1 for s in sents if len(s) > 30)
chars = max(sum(1 for c in text if not c.isspace()), 1)
puncts = sum(1 for c in text if c in '，。！？；：、…—""\'\'')
avg = sum(len(s) for s in sents) // total
print(f'sentences={total}; short_lt15={100*short//total}%; mid_15to30={100*mid//total}%; long_gt30={100*lng//total}%; avg_len={avg}; punct_density={100*puncts//chars}%')
PYEOF
```

실제 출력 형태는 `sentences=6; short_lt15=66%; mid_15to30=33%; long_gt30=0%; avg_len=12; punct_density=15%`입니다.

출력된 `short_lt15 / mid_15to30 / long_gt30 / avg_len / punct_density` 수치를 `style-profile-protocol.md` 템플릿 40번 줄의 `{...X% / Y% / Z%}` 자리 표시자에 직접 입력하세요. `confidence: high`는 확정적 측정값이므로 샘플링 추정이 아닙니다.

**Bash를 사용할 수 없을 때의 폴백**（자식 에이전트 컨텍스트 등 극한 상황에만 해당하며, 메인 스레드에서는 트리거되지 않습니다）：

- 이 단계를 건너뛰세요. 문장 길이 섹션에 「Bash 도구를 사용할 수 없어 결정론적 통계를 건너뜁니다」라고 기록합니다.
- `confidence: low`인 경우, narrative-writer가 기본 Gate D로 양보합니다(문장 길이 표준으로 보정).

### Step 5: 원문 앵커 포인트 세그먼트 선택 (4-6 섹션)

Step 3의 출력에서 나온 챕터 톤에서 커버리지가 가장 높고 프로젝트에 필요할 가능성이 있는 4-6가지 톤을 선택합니다(우선 커버: 긴장/슬픔 또는 억압/편안함 또는 따뜻함/열혈). 특정 톤이 참고 도서에서 3개 챕터 미만이면 억지로 만들지 마세요. 문체 파일에 건너뜬 사항을 명시합니다. 각 톤마다 1개 챕터를 앵커 챕터로 선택합니다.

**동일 톤 다중 챕터 선택 규칙**:

1. **L1 쾌감 포인트 유형 최강 매칭**: 해당 장의 `_요약.md` 「핵심 이벤트」+ 기조 시퀀스를 참고하여 쾌감 포인트가 가장 두드러진 장을 선택
2. **L2 원문 장 길이가 일일 업데이트 목표에 가장 근접**: Step 4에서 이미 장 경계를 절단한 경우 원문 장 슬라이스로 글자 수 추정; 원문을 절단할 수 없는 경우 `_요약.md`의 플롯 포인트 수량으로만 복잡도를 근사하며, 요약 파일 길이를 원문 장 글자 수로 간주하지 않음
3. **L3 장 번호 최소**: 가장 초기 장 = 저자의 가장 canonical한 voice(연재 표류의 영향을 받지 않음)

앵커 포인트 슬라이싱:

- Step 4 grep으로 획득한 장 행 번호 사용
- 해당 장의 원문에서 1개 문단 300-500자를 선택합니다(대화+동작이 얽힌 문단을 우선하며, 순수 독백/순수 설정 문단은 제외).
- `Read offset limit`으로 추출하되, 원본 문장부호와 문단 줄바꿈을 유지합니다.
- **앵커는 반드시 문자 단위로 연속 추출하고, 개작/축약/건너뛰기/병합을 금지합니다**: narrative-writer가 앵커를 few-shot으로 직접 학습하므로, 표기된 행 번호로 원문을 역추적할 수 있어야 합니다. 저장 전 각 문단에서 1-2문장을 `grep -F`로 `원문/원문.txt`에서 검색하여 확인합니다. grep 결과가 없으면 개작되었거나 병합된 것입니다. 이 경우 충실한 연속 구간으로 재추출합니다. 중간 과도 문단을 건너뛸 필요가 있으면 각각의 실제 행 번호를 표기합니다(예: 「행264-267 + 행269-270」). 인용 블록 내에서 「（……중략……）」로 명시적으로 단절을 표시하며, 연속된 행 번호 구간으로 연속성을 위장하면 안 됩니다.

### Step 6: 저장

[style-profile-protocol.md](style-profile-protocol.md) 템플릿에 따라 `분해문서고/{책명}/문풍.md`를 작성합니다.

- **문풍 파일은 반드시 분해문서고에 남아 있어야 합니다**(`분해문서고/{책명}/문풍.md`), **analyze가 직접 `대비/` 또는 작성 프로젝트 디렉토리에 기록하면 안 됩니다**——분해문서고는 데이터 소스이고, 해당 책이 다른 프로젝트의 외부 벤치마크로 명시적으로 선택되었을 때만 story-import 또는 story-long-write가 처음으로 동기화하여 `대비/{책명}/`에 반영합니다
- 각 섹션에 `confidence: high/med/low` 표시(내부용으로 작성 agent의 판단 근거 제공, 일반 사용자는 무시 가능):
  - `high`: 데이터가 분해문 산출물에서 직접 나옴(예: "쓰기 기법"이 분해문 보고서를 직접 인용)
  - `med`: 샘플에서 귀납했고 샘플 충분(예: 톤 시퀀스가 ≥10개 장의 요약 통계에서 파생)
  - `low`: 샘플 부족 또는 샘플링 실패(예: 앵커 누락, Bash 불가능으로 인해 Step 4 문장 길이 통계 생략)
- 「계층별 모방 제안」은 반드시 기초층 / 고급층 / 적응층으로 나누기; 기초층은 어휘, 문형, 묘사와 대사 습관만 작성, 고급층은 리듬, 복선, 시점과 장면 연결 작성, 적응층은 어떤 것이 사용 가능한지, 어떤 것이 이 프로젝트에서 오류를 일으키기 쉬운지 작성; 고유명사, 특징적 대사, 독특한 장면, 사건 순서는 명확히 복제하지 않기
- 글자 수 예산: 하드 상한 ~4000 자. **설명 구간 ≤ 1800 자 + 앵커 포인트 4-6 구간 × 300-500 자**
- Step 4 실패 시（장절 구분 기호 인식 불가）→ 「생성 기록」에 `문체 사용 가능: 아니오: 장절 구분 기호를 인식할 수 없음` 작성; 원문 앵커 포인트 구간은 모두 플레이스홀더 "원문 누락, 수동 보충 필요"로 채우기, confidence는 모두 low

## 실패 모드와 하향 조정

| 시나리오 | 하향 조정 전략 |
|---|---|
| `원문/원문.txt` 없음 | Step 4-5 건너뜀; 문풍 파일은 설명 단락만 포함; 「생성 기록」에 `문풍 사용 가능: 아니오: 원문 누락` 작성 |
| `장절/*_요약.md` 개수 <3 | Step 3 기조 시퀀스 건너뜀; 감정 교대 단락 confidence: low 표시 |
| `장절/제1-3장_심층 분석.md` 누락 | Step 2 건너뜀; 대화 잠재 의도 단락을 분석 보고서에서 대체; confidence: low |
| `분석 보고서.md` 없음 | **Stage 6 중단**, 사용자에게 분석 미완료 안내, 먼저 Stage 5 완료 필요 |

## chapter-extractor와의 관계

**chapter-extractor는 수정하지 않음**. 문체는 기존 필드(기조/주제 태그/참고 요소)에서 직접 정리하여 생성하면 됩니다.

문장 길이 / 문장부호 밀도는 Step 4의 크로스플랫폼 Python 1-liner가 Stage 6 메인 스레드에서 직접 계산하며, chapter-extractor에 의존하지 않습니다.

## 작성 엔드와의 관계

- analyze Stage 6에서 `拆文库/{서명}/문체.md` 작성
- story-import가 외부 벤치마크를 명시적으로 바인딩하거나 story-long-write가 처음으로 `拆文库/{서명}/`을 참조할 때, 프로젝트 `{프로젝트}/대표/{서명}/`에 동기화하고 **문체 포함**(拆文 보고서와 동등한 대우); 현재 임포트 중인 본 저작을 해당 외부 벤치마크로 삼으면 안 됩니다.
- 작성 단계(story-long-write)의 일일 업데이트 사이클이 `{project}/benchmark/{book-name}/style.md`를 읽습니다(벤치마크 도서 경로 조회 규칙에 따라, `dismantled-library/{book-name}/`으로 폴백).

## 문풍 단독 재생성

현재 분해 산출물에서 `style.md`만 누락된 경우, 본 SOP의 6단계(Stage 6만 해당)를 직접 실행할 수 있으며 Stage 0-5를 다시 실행할 필요가 없습니다. 전제 조건은 `_progress.md`가 현재 챕터 경계 계약을 만족해야 합니다. 트리거: 사용자가 직접 "벤치마크 도서 X에 대한 문풍 생성" 또는 "문풍 재생성"이라고 말합니다.
