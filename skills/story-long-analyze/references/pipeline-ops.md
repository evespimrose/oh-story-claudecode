# 파이프라인 운영 참조

story-long-analyze 분해 파이프라인 운영 도구 문서: `_progress.md` 템플릿, 오류 처리, 복구 메커니즘 작업 절차.

> 품질 임계값(신뢰도 / 커버리지 / 중복률)은 [material-decomposition.md 품질 임계값 체계](material-decomposition.md)를 참조하세요.

---

## _progress.md 템플릿

```markdown
# 심층 분해 진행 상황: {서명}
- 소설: {제목} | 총 장 수: {N} | 출력 디렉터리: {경로} | 시작: {날짜}
- 최종 상태: {pending/paused_after_stage1/completed/completed_with_errors}
- schema_version: 2
## 파이프라인 진행 상황
| 단계 | 상태 | 진행률 | 비고 |
|------|------|------|------|
## 챕터 경계(Stage 0 챕터 경계 하위 단계 결과물, 유일한 기준)
| 장 번호 | 제목 | 시작 행 | 글자 수 |
|------|------|--------|------|
## 청크 진행 상황
| 청크 | 챕터 | 상태 |
## 실패 기록
| 유형 | 챕터/단계 | 오류 메시지 | 재시도 상태 |
|------|----------|---------|---------|
## 품질 검사
| 검사 항목 | 단계 | 결과 | 수정 |
## 캐릭터 병합
| 병합 전 | 병합 후 | 근거 | 확인 |
## 중단점
- 마지막 처리: 제{N}장 | 현재 단계 | 다음 작업
```

**schema_version 설명**:

| 버전 | 의미 |
|------|------|
| 2 | 현재 규약: 「장 경계」 표 포함(Stage 0 장 경계 하위 단계 결과물). Stage 1/2/6은 모두 이 표를 슬라이싱의 참값(Ground Truth)으로 사용하며, 더 이상 각각 regex를 실행하지 않음 |

`schema_version: 2` 또는 「장 경계」 표가 누락된 경우 이어서 실행할 수 없습니다. Stage 0 장 경계 하위 단계에서 `_progress.md`를 재구축한 후 재개하세요.

**최종 상태 값 설명**:

| 상태 값 | 의미 |
|--------|------|
| `pending` | 파이프라인 진행 중, 아직 완료되지 않음 |
| `paused_after_stage1` | Stage 1 정지 지점 일시 중지—Stage 0/1 완료, `빠른_미리보기.md` 생성됨, 사용자가 Stage 2-6 진행 여부를 결정할 때까지 대기. 재개 시 Stage 0/1을 건너뛰고 Stage 2부터 시작 |
| `completed` | 전체 파이프라인 Stage 0-6 완료 |
| `completed_with_errors` | 전체 파이프라인 완료되었으나, 단일 장/단계 실패 발생(자세한 내용은 「실패 기록」 표 참조, 분석 보고서에 명시됨) |

## 스토리 유닛 리스트 추가 구축 (기존 도서)

트리거: 사용자가 "스토리 유닛 리스트 보충"이라고 말하거나, 집필 측 검색 결과 `스토리/README.md`에 「스토리 유닛 리스트」 표가 없는 경우.

동작: 기존 `분석 라이브러리/{도서명}/스토리/*.md`(또는 `벤치마킹/{도서명}/스토리/*.md`) 각 스토리 유닛 헤더의 제목 / 유형 / 브릿지 태그 / 장 범위 필드를 읽어, output-templates.md의 「스토리 유닛 리스트」 표 템플릿에 따라 `스토리/README.md`의 리스트 표를 기계적으로 재구축합니다. 프로젝트 `벤치마킹/{도서명}/` 뷰가 존재할 경우 동기화합니다. 원문은 읽지 않으며, 어떤 Stage도 재실행하지 않고, 스토리 유닛 내용을 수정하지 않으며, `리듬.md` / `감정_모듈.md`는 건드리지 않습니다. 기존 스토리 유닛의 「장 범위」 행에 글자 수 정보가 없는 경우, 분량 열에는 「총 {N}장」만 작성하고 글자 수는 「알 수 없음」으로 기록하며, 임의로 생성하지 않습니다.

집필 측 소비 지점에서 리스트가 없는 도서는 자동으로 파일별 검색으로 폴백(Fallback)합니다(story-long-write의 outline-structure-theory.md 「벤치마킹 리듬 마이그레이션」 1단계 참조). 추가 구축은 가속화를 위한 것일 뿐, 차단 항목(Blocking item)은 아닙니다.

## 오류 처리

| 시나리오 | 처리 |
|------|------|
| 장 인식 실패 | 형식 확인 안내, 사용자 정의 정규식 지원 |
| 블록 중단 | `_progress.md`를 읽어 중단 지점부터 복구 |
| 병합 품질 미달 | 고립된 플롯 2차 분류, 임계값을 0.5로 완화 |
| 캐릭터 병합 충돌 | 확인 대기 목록에 기록 |
| 출력 디렉터리 충돌 | 덮어쓰지 않고 추가; 충돌 시 `[재분석]` 표시 |

## 복구 메커니즘 작업 단계

1. 파이프라인 시작 시 출력 디렉터리에 `_progress.md` 파일이 있는지 확인
2. `schema_version: 2` 및 '챕터 경계' 표 검증; 하나라도 누락되면 중단하고 Stage 0 챕터 경계 하위 단계부터 진행 상태 파일을 재구성하도록 안내
3. 중단점 정보 읽기(마지막 처리 챕터 + 현재 단계 + 최종 상태)
4. **중단점 상태가 `paused_after_stage1`인 경우**(Stage 1 정지 지점) → Stage 0/1을 건너뛰고 Stage 2부터 챕터별 요약을 재개하며, 이미 완료된 시놉시스 및 황금 3장은 다시 실행하지 않음
5. 기타 중단점 상태 → 중단점이 포함된 블록의 시작 챕터부터 복구하며, 해당 블록의 기존 출력을 덮어씀
