# 短篇正文格式

> 본문을 쓰기 전에 반드시 읽는다. 이 문서는 장 표기, 단락 형태, 대화, 문장부호, 메타정보 금지만 다룬다.
> 작성법(감정 외화, 훅 밀도, 반전, 마무리)은 `short-craft.md`와 장르 패키지에서 다루며 여기서 반복하지 않는다.
> 이것이 현재 저장소의 기본 납품 형식이다. 사용자나 목표 플랫폼이 별도 요구를 제시하면 사용자·플랫폼 요구를 우선한다.

---

## 장 표기

전체에서 한 가지 형식만 통일해 사용하며 섞지 않는다.

| 형식 | 적용 플랫폼 | 예시 |
|------|----------|------|
| `###1.` | 단편 기본 | `###1.` `###2.` `###3.` |
| `###第N章` | 판치에 / 치마오 / 고언 | `###第一章` `###第二章` |
| `1.`(순수 숫자, `###` 없음) | 즈후 염언 | `1.` `2.` `3.` |

단편에는 간결한 `###1.` 또는 순수 숫자 형식을 권장한다. 판치에 계열에서 조금 긴 장에는 `###第N章`을 사용한다.

---

## 단락: 두 가지 플랫폼 템플릿

단편 본문의 형태는 플랫폼에 따라 두 가지로 나눈다.**不设统一的「每段 ≤ 3 句」「800-1500 字 / 节」硬线**，那是长篇迁移过来的产物，会把短篇切成一样长的提纲。先认平台底色，再按 `short-craft.md` 的疏密原则分配字数。

### 헤이옌: 한 문장 한 단락, 여백을 살린 빠른 읽기

- 一句一段为主，多换行制造下坠和停顿感。
- 节奏密，每节体量小，节尾必留钩。
- 单句成段是常态，不要为了「凑够字数」把句子焊回长段。

模板示意：

```
###1.

我们家有个规矩，每年清明节都要拜"福祸盘"。

一个盘子，一半装着山珍海味，一半盛着清汤寡水。

哥哥抽中了肉，爸妈奖励他一个大红包。

轮到我，我再次抽中了那碗清汤。
```

### 판치에·치마오: 짧은 단락을 바탕으로 서술과 대화를 교차

- 短段仍是手机阅读的底色，但**允许多句回溯叙述段和对话交织**：一段里可以有内心独白、回忆补刀、动作，再接对话。
- 古言 / 世情可写更长的叙述段，承载完整的情绪链和场景铺陈。
- 爽点、打脸、反转处压短（可单句成段）；过场、信息交代一句带过。

模板示意：

```
###第一章

我把热汤端到他面前的时候，他正低头看手机，屏幕亮着白月光的名字。三年了，我以为熬过了最难的日子，原来熬的只是我自己。

"以后这种事不用你做。"他头也没抬，"她不喜欢闻油烟味。"

我端着碗的手顿了一下。
```

### 두 템플릿의 공통 강제 규칙(모든 플랫폼)

- 正文相邻段落之间**只允许一个换行符 `\n`**，不得出现空行或连续换行 `\n\n`（紧密排列）。章节标记前后另算。
- **无缩进**：不用 `　　`（全角空格）或半角空格缩进，平台渲染器自行处理。
- **禁正文段落 Markdown**：除统一的小节 / 章节标记（如 `###1.`），正文段落里不用加粗 `**`、斜体 `*`、标题 `#`、分隔线 `---` 等。
- 长短交错，忌通篇同长度。把每段切成同一字数，正是 AI 腔来源。

## 대화

### 인용부호

| 우선순위 | 형식 | 적용 |
|--------|------|------|
| 우선 | `"대사 내용"`(반각) | 단편 기본, 판치에, 홍궈, 헤이옌 |
| 플랫폼·프로젝트 지정 | `「대사 내용」` | 즈후 염언, 일부 고언, 사용자 지정 |

**기본은 `""`을 사용한다.** 사용자가 지정했거나 플랫폼이 염언 스타일이면 `「」`을 사용하며, `「」`을 오류로 보고 바꾸지 않는다.

### 规则

1. 对话**独立成行**，不嵌在叙述段落里。
2. 用动作代替对话标签：少用「他说」「她道」「他笑了笑说」，改成动作 beat + 对话；普通的「说」按语境可留。
3. 两人连续对话省略标签，靠内容区分说话人。

正确：

```
她把杯子放下。
"你走吧。"
他没有动。
"我说，你走吧。"
```

错误：

```
她把杯子放下，说道："你走吧。"他没有动，她又说："我说，你走吧。"
```

## 문장부호 강제 규칙

**이 저장소의 본문에는 `……` / `——` / `—` / `--`를 통일해 사용하지 않는다.**(AI 문체 제거 스크립트와 hook이 강제하는 프로젝트 차원의 금지선) 서술·대화·심리 묘사 모두에 적용하며 대화도 예외가 아니다.

停顿、哽咽、未尽、被打断、留白，一律用以下手段实现：

- 短句、句号、逗号断开。
- 动作 beat（「她顿了一下」「他攥紧了拳」）。
- 换行 / 单句成段。

其余标点跟语气走：

| 语气 / 功能 | 标点 | 防线 |
|---|---|---|
| 压迫 / 冷静 / 克制 | 短句、逗号、句号，必要时冒号压判断落点 | 不人工加感叹号，也不通篇句号化 |
| 质问 / 反问 | 问号 + 短促追问 | 别每句都以 `？` 结尾 |
| 爆发 / 打脸 | 真爆点用 1 个感叹号，连续爆发最多 1-2 处 | 禁 `!!!`、禁整段喊叫式感叹 |
| 信息揭示 / 判断落点 | 冒号、单句成段制造落点 | 别写论文式分号串 |

题材包范例里若出现 `……`，只为示意手法，落到正文按本条改写。

## 본문에 장 메타정보를 섞지 않기

장 번호와 집필 작업 용어는 제목·소절 표기·파일명·추적 기록에만 허용한다. 본문 서술·대화·심리 묘사에는 **다음 표현을 넣지 않는다**:

```
第[一二三四五六七八九十百千万两0-9]+章 | 上一章 | 上章 | 前一章 | 本章 | 这一章 | 前文 | 后文 | 伏笔 | 细纲 | 读者
```

인물이 감지할 수 있는 사건 기준점이나 상대적 시간으로 바꾼다. 예: ‘1장의 그 3초간 발포보다 아프다’를 ‘그 3초간 발포보다 아프다’로 바꾼다.

例外：角色在故事世界内真实阅读 / 讨论「第 X 章」文本，或角色真实身为作者 / 读者并谈论读者身份时，可保留。

## 플랫폼 적용표

| 平台 | 章节标记 | 对话格式 | 段落底色 | 特殊要求 |
|------|----------|----------|----------|----------|
| 知乎盐言 | `1.`（纯数字） | `「」` | 短段 + 叙述交织 | 导语需单独标注 |
| 番茄 | `###第N章` | `""` | 短段为底色，允许叙述交织对话 | 首段需有吸引力 |
| 红果 | `###1.` | `""` | 短段为底色 | 无 |
| 黑岩 | `###1.` | `""` | 一句一段，多换行留白 | 节尾必留钩 |

사용자가 플랫폼을 지정하지 않으면 단편 공통 형식인 `###1.` + `""` + 판치에 계열의 짧은 단락을 기본으로 한다.

## 각 단락 작성 후 빠른 점검

- [ ] 段落形态符合目标平台模板（黑岩一句一段 / 番茄系短段交织叙述）？没把它切成同一字数的提纲？
- [ ] 相邻段落之间只有一个 `\n`，没有空行 / `\n\n`？
- [ ] 无缩进（没有 `　　` 或空格）？
- [ ] 标题 / 小节标记之外，正文段落没用 `**` `*` `#` `---` 等 Markdown？
- [ ] 对话独立成行，引号风格符合平台（盐言 `「」` 合法），对话标签没机械化？
- [ ] 正文（含对话）里没有 `……` / `——` / `—` / `--`，停顿改用短句 / 动作 / 换行？
- [ ] 标点跟语气走：没通篇句号化，没乱撒 `？` / `！`？
- [ ] 正文没混入 `第N章` / `上一章` / `本章` / `前文` / `后文` / `伏笔` / `细纲` / `读者` 这类元信息词（故事内真实阅读 / 真实读者身份语境除外）？
