# 소재 선정 의사결정: 랭킹 데이터에서 "무엇을 써야 터질까"까지

랭킹 분석 결과를 즉시 사용 가능한 소재 선정 제안으로 변환: **추천 소재, 흥행 이유, 실현 가능성, 검증 방법**.
페이즈 5에서는 본 문서의 방법을 사용하여 `소재_선정_의사결정.md`를 생성합니다. 이는 시장 관점의 소재 초안으로, "흥행 이유"를 먼저 가설로 설정한 뒤 작품 분석(story-long-analyze)을 통해 사후 검증하며, 집필(story-long-write) 단계에서 즉시 활용합니다.

## 의사결정 라우팅

| 현재 작업 내용 | 참고 섹션 |
|-----------|--------|

## 소재 선정 4단계

모든 추천 소재는 다음의 4단계를 반드시 거쳐야 합니다.

1. **흥행 이유(가설 단계)**: 랭킹에서 **반복적으로 나타나는 샘플**(단일 사례 제외) + 새로운 요소 추출을 통해 "이 방향은 X 구조/클리셰/캐릭터 설정을 통해 독자층을 공략하여 흥행할 수 있다"는 결론을 도출합니다. 단일 작품의 랭킹 진입은 예외일 뿐입니다(랭킹 분석 원칙 1: 여러 작품이 반복되어야 유효한 신호). 여기서는 가설만 작성하고 `작품 분석 검증 대기`로 표시하며, 최종 확정은 작품 분석 후 내용을 채워야 합니다.
2. **시장 검증**: 랭킹 내 동일 방향의 작품 수 + 추세(↑/→/↓) + 반례(동일 방향에서 실패하거나 용두사미로 끝난 사례). 샘플이 많고 추세가 안정적일수록 신뢰도가 높습니다.
3. **차별화 포지셔닝**: 작가의 강점 × 시장의 틈새 = "기존 랭킹 작품들과 내 작품의 차이점". 차별화가 없으면 동질화로 인해 시장 진입이 어렵습니다.
4. **실현 가능성 + 리스크 + 검증 작업**: 실현 가능성 상/중/하(다음 섹션 규칙 참조), 예상되는 주요 실패 요인, 집필 전 저비용 검증 방법(통상: "초반 황금 3장을 먼저 써서 연독률을 테스트하고, 결과가 좋지 않으면 교체")을 제시합니다.

---

## 실현 가능성 판단

3단계로 구분하며, 샘플이 부족할 때는 "상" 등급을 부여하지 마세요. 소수의 데이터로 근거 없는 자신감을 갖지 않도록 주의해야 합니다.

| 실현 가능성 | 의미 | 조건 |
|--------|------|------|
| 상 | 안심하고 집필 가능 | 동일 방향 랭킹 샘플 충분(≥15, 소규모 플랫폼 ≥10) + 추세 ↑ 또는 → + 작가의 소재 역량 충분 + 차별화 공간 확보 |
| 중 | 집필 가능하나 선행 검증 필요 | 샘플은 충분하나 추세 ↓ / 또는 차별화 불분명 / 또는 작가의 소재 역량이 완벽하지 않음 |
| 낮음 | 권장하지 않음 | 동일 방향 포화(실패 사례 많음) / 또는 작가의 소재 부족 / 또는 플랫폼 성향과 불일치 |

**필수 규칙**: 특정 방향의 근거가 되는 랭킹에 `[데이터 희소]`(유효 항목 < 15, 소규모 플랫폼 < 10, 즉 랭킹 분석 품질 검사에서 설정한 희소 임계값)라고 표시된 경우, 해당 방향에는 **'높음'을 부여할 수 없으며**, 강제로 '중간'으로 낮추고 "표본 부족, 표본을 충분히 수집하거나 테스트 후 결정"이라고 명시해야 합니다.

**내장 지식 모드**: 랭킹 데이터 없이 순수하게 지식 베이스의 트렌드에 의존할 경우, **모든 방향에 일괄적으로 '중간'을 부여**하며, 사유에는 "일반적 인지에 기반함, 랭킹 검증 없음, 집필 전 반드시 랭킹을 분석하거나 저비용 테스트 필요"라고 작성합니다. '높음'은 허용되지 않습니다.

## 소재 결정.md 템플릿

```
# 소재 결정: {플랫폼/방향}
- 랭킹 분석 날짜: {YYYYMMDD}     # 데이터 최신성; 집필 시점에 만료된 경우 재분석 알림 발생
- 데이터 출처: {랭킹 파일명 / 내장 지식}

## 추천 소재

### 소재 1: {한 줄 요약 방향}
- 소재 조합: {메인 장르 + 서브 장르/클리셰}
- 타겟 독자: {페르소나}
- 핵심 셀링 포인트: {독자가 읽어야 할 이유}
- 흥행 가능 이유: {X 구조/클리셰가 왜 통하는지} (가설, `분석 검증 대기 중`)
- 차별화 포인트: {기존 랭킹 작품들과의 차이점}
- 실현 가능성: 높음/중간/낮음 — {사유, 동일 방향 작품 수 + 트렌드 명시}
- 실패 리스크: {가장 무너지기 쉬운 부분}
- 검증 작업: {집필 전 저비용 검증 방법}
- 분량/플랫폼: {권장 글자 수 범위 + 목표 플랫폼}

### 소재 2 ...
### 소재 3 ...
```

2~3개의 주제가 적당하며, 실현 가능성 순으로 정렬합니다(높은 순서대로).

## 결과물

1. 이번 차트 스캔의 출력 디렉터리(차트 파일과 동일한 디렉터리)에 작성합니다: `{outdir}/주제_결정.md`. 차트 스캔은 소설 프로젝트가 아직 없는 디렉터리에서 실행되는 경우가 많으므로, 결과물을 프로젝트에 직접 작성하지 않고 여기에 저장합니다.
2. 사용자에게 경로를 안내하고 다음 단계를 설명합니다: "집필을 시작할 때 소설 프로젝트가 이 디렉터리에 생성되었거나 이 디렉터리와 같은 계층(상위 디렉터리 공유)에 있다면, `/story-long-write`가 자동으로 찾아 확인을 요청합니다. 거리가 더 멀다면 `주제_결정.md`를 소설 프로젝트의 루트 디렉터리로 복사하거나 집필 시작 시 경로를 붙여넣으세요. '흥행 이유'를 확인하고 싶다면 먼저 `/story-long-analyze`로 벤치마킹 도서를 분석하세요. 분석이 끝나면 해당 내용이 채워집니다."
3. 후속 연계(본 파일에서는 실행하지 않으며 설명만 제공): 도서 분석은 요약 보고서가 생성된 후 해당 주제의 '흥행 이유'를 다시 채워 넣습니다. 집필 Phase 1에서는 `주제_결정.md`를 읽어 집필 시작점으로 삼습니다.
