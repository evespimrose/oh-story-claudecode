# workflow-setup.md: 집필 시작 워크플로(Phase 1-3)

이 문서는 “집필 시작/설정 구축/개요 작성” 상황을 위한 전체 지침이다. `SKILL.md`의 Phase 1-3에서 분리해 정리했다.
`SKILL.md`에는 상황별 라우팅과 정박 규칙만 남기며, 어느 Phase에 들어가기 전에도 이 문서의 해당 절을 읽고 그 절차에 따라 실행한다.

> 이 세 Phase는 책마다 한 번만 실행한다(새 권을 시작할 때는 Phase 2/3을 증분 보완한다). 일일 연재 이어쓰기와 단일 장 집필에는 이 문서가 필요하지 않으며,
> `SKILL.md`의 Phase 4와 `workflow-daily.md`를 따른다.

---

### Phase 1: 기획 방향 확인

**먼저 기획 결정 확인**: 프로젝트 루트에 `选题决策.md`(story-long-scan Phase 5 산출물)가 있으면 읽는다. 실행 가능성이 가장 높은 추천 기획을 첫 집필 방향으로 삼아 사용자에게 “시장 조사 결과 X를 쓰라는 권고입니다(흥행 가능성이 높은 이유 Y, 차별화 포인트 Z). 이 방향으로 시작할까요?”라고 확인한다. `扫榜日期`도 확인해 오래된 경우 “시장 데이터가 만료되었을 수 있으니 다시 조사하는 편이 좋습니다”라고 알린다. 사용자가 동의하면 해당 기획의 장르·판매 포인트·차별화 방향을 가지고 Phase 2로 들어간다.

파일이 없으면 먼저 자동 검색한다. 프로젝트 루트와 그 상위 디렉터리에서 시작해 최대 3단계 아래까지 파일명으로 `选题决策.md`를 찾되 숨김 디렉터리는 건너뛴다. 수정 시간 기준 최신 2개를 가져온다. 찾으면 AskUserQuestion으로 후보를 제시한다(경로와 파일 안의 `扫榜日期`, 그리고 “내가 직접 경로를 제공하겠습니다”와 “모두 사용하지 않겠습니다” 선택지를 함께 표시). 하나를 고르면 프로젝트 루트로 복사한 뒤 앞의 절차대로 읽는다. “내가 직접 경로를 제공하겠습니다”를 고르면 사용자에게 경로를 받아 같은 방식으로 프로젝트 루트에 복사한다. “모두 사용하지 않겠습니다”를 고르면 아래의 일반 질문으로 진행한다. 검색되지 않으면 “시장 조사로 생성된 `选题决策.md`가 있나요? 프로젝트 루트에 두거나 경로를 붙여 주세요. 없다면 아래 질문에 바로 답해 주세요.”라고 한 번 묻고, 여전히 없으면 아래 일반 질문으로 진행한다.

사용자에게 이미 방향이 있다면 아래 방향 질문은 건너뛰되, 먼저 다음의 **대조 컨텍스트 로드**(대조 도서 탐색 포함)를 수행한 뒤 Phase 2로 들어간다.

사용자에게 방향이 없다면 다음을 묻는다.

**“독자에게 어떤 감정을 느끼게 하고 싶나요? 참고하고 싶은 책이 있나요? 당신의 강점은 무엇인가요(상상력이 좋음/문장력이 좋음/리듬감이 좋음/생활 경험이 풍부함)?”**

#### 대조 컨텍스트 로드

> **拆文库/对标 관계**와 **대조 도서 경로 찾기**의 정의는 `SKILL.md`의 “경로 및 용어 규약”을 참조한다. 이 문서와 Phase 4는 같은 규칙을 공유한다.

**대조 도서 탐색(아래의 반응형 로드보다 먼저 실행)**: 사용자가 대조 도서를 직접 언급했는지와 상관없이 먼저 `拆文库/`를 장르별로 훑어 적극적으로 추천한다. 사용자가 먼저 말을 꺼내기를 기다리지 않는다.

1. `ls 拆文库/`(데이터 소스)와 프로젝트의 `对标/`(참조 뷰)에 있는 도서 목록을 확인한다. 현재 프로젝트 디렉터리명, `.active-book`, `设定/题材定位.md`의 본서 정보를 기준으로 현재 작품을 먼저 식별하고, 동명이거나 현재 본문을 출처로 하는 `拆文库/{当前书}/`는 제외한다. `story-import`가 재구축 과정에서 만든 본서의 분석은 대조 후보가 아니며 `对标/`로 복사해서도 안 된다. 제외하고 남는 후보가 없으면 4번으로 건너뛴다.
2. 각 도서의 장르를 읽는다. 단편은 `拆文库/{书}/_meta.json`의 `genre_detected`를 읽고, 장편은 `概要.md`의 머리말 또는 `拆文报告.md`의 “基本信息” 중 “题材”를 읽는다. 이를 본서의 장르·방향과 비교해 동일 장르/약한 관련/무관으로 분류한다.
3. 동일 장르 또는 약한 관련 후보가 있으면 AskUserQuestion으로 추천한다(후보 도서와 “모두 사용하지 않음”, “다른 책을 분석” 선택지를 제시). 주 대조 도서 한 권은 문체와 본문을 위한 기준으로 삼고, 나머지는 보조 대조 도서로 사용한다. 선택한 뒤 `设定/题材定位.md`의 “对标登记”에 `主对标书`와 `对标书列表`로 기록한다(Phase 2에서 파일로 반영하며 여기서는 선택만 기록). 또한 `SKILL.md`의 “경로 및 용어 규약”에 있는 “대조 도서 최초 인용” 규칙에 따라 선택한 도서를 `拆文库/{书}/`에서 `对标/{书}/`로 복사한다.
4. 후보가 없으면 대조 도서 없이 진행한다(개요는 8개 노드에 따라 자체 구성하며 Phase 3 참조). 사용자가 대조 도서를 원하면 먼저 `/story-long-analyze`로 한 권을 분석할 수 있다.

사용자가 대조 도서를 언급했거나 작업 디렉터리에 `对标/` 디렉터리가 이미 있으면 다음을 수행한다.

1. 위 “대조 도서 탐색” 1번과 같은 기준으로 현재 작품을 식별하고, 동명이거나 현재 본문을 출처로 하는 `对标/{当前书}/`는 제외한다. 오래된 가져오기 프로젝트에는 잘못 만들어진 자기 대조 디렉터리가 남아 있을 수 있다. 외부 대조 도서가 없으면 아래 단계로 들어가지 않고 대조 도서 없이 진행한다.
2. 대조 도서 경로 찾기 규칙에 따라 `剧情/情绪模块.md`와 `剧情/节奏.md`를 확인한다.
3. 두 핵심 산출물 중 하나라도 없으면 반드시 중단하고 `missing_primary_contract: true`를 설정한 뒤 `repair_action`을 제시한다: `/story-long-analyze` Stage 3+를 다시 실행하거나 `/story-import`를 다시 실행한다. `拆文报告.md`, 장 요약, 스토리라인으로 대체해서는 안 된다.
4. 두 핵심 산출물이 모두 있으면 먼저 `剧情/情绪模块.md`의 독자 요구·감정 엔진·재현 가능한 모듈을 읽고, 이어 `剧情/节奏.md`의 핵심 정보 진행·감정 자극점·폭발 리듬을 읽는다. `拆文报告.md`는 사람이 읽는 개요로만 사용한다.
5. 인물·일반 플롯 단위·설정 하위 디렉터리가 있으면 집필할 때 필요한 모듈을 그때그때 불러온다.

답변에 따라 다음과 같이 매칭한다.

- 상상력이 좋음 → 시스템물, 제천류, 무한류
- 문장력이 좋음 → 선협, 역사, 문예 지향 현대물
- 리듬감이 좋음 → 현대식 쾌감물, 회귀물, 게임물
- 생활 경험이 풍부함 → 업계물, 현대 일상물, 농경물

#### Agent 호출: story-architect

`story-architect`는 고수준 구조 설계 agent다. 가벼운 장르 포지셔닝은 우선 메인 대화에서 처리하고, 복잡한 세계관·다중선 구조·강한 반전 설계가 필요하거나 사용자가 명시적으로 요구할 때만 `story-architect`를 호출한다. 기획 방향을 확정한 뒤 프로젝트에 해당 agent가 배포되어 있다면(`.claude/agents/story-architect.md`의 존재 여부 확인), 다음과 같이 spawn해 장르 분석과 핵심 콘셉트 설계를 보조하게 할 수 있다: `Agent(subagent_type: "story-architect", prompt: "项目目录：{dir}\n任务类型：题材定位\n查询参数：{用户选择的方向+对标信息}")`. agent를 사용할 수 없으면 메인 스레드가 직접 실행한다.

> **story-architect 계약 요약(spawn 시 반드시 원문 그대로 첨부)**: 배포된 `story-architect` agent는 이 skill의 `references/reader-contract-and-progression.md`를 알지 못한다. spawn prompt에 다음 요약을 넣어 schema를 맞추지 않으면 메인 스레드와 위임 결과가 서로 다른 진행 규칙을 사용하게 된다.
> - **최종 국면 비축 경계**: 최종 비장의 카드(최종 숙적/최종 진실/금손의 상한/정체성의 종착점/핵심 감정의 종착점)는 일회성 자원이며 권마다 해금한다. 승급 단계(경지/레벨/지도/세력 단계)는 남은 단계 수에 따라 순차적으로 해금하며 단계를 건너뛰지 않는다.
> - **초과 인출 두 질문**(하나라도 “예”면 되돌리거나 개요를 수정해야 함): ① 아직 이 단계에서 해금해서는 안 되는 최종 비장의 카드를 사용했는가? ② 어떤 승급선이 천장에 가까워져 이후 이어 갈 단계가 남지 않았는가?
> - **플롯 단위**: 권별 개요 안에 플롯 단위 카드를 작성한다. 단위 ID, 주 추진선 1개와 전과선 여러 개(한 전투에서 여러 전과를 얻어도 됨), 장 단위 최소 추진량(빠른 전개의 경우에도 눈에 보이는 사건과 쾌감 포인트의 하한)을 포함한다.
> - **세부 개요 필드**: 각 장의 세부 개요에는 단위 ID/위치와 주인공 목표/핵심 선택이 반드시 들어가야 한다. 기존 필드 `代价兑现`은 `行动成本（可无）/收益归属`으로 대체한다. 행동 비용은 없을 수 있으며 억지로 대가를 만들지 않는다. 수익의 귀속은 반드시 눈에 보이게 한다.
> - **독자 계약과 주인공 대리권**: 주인공은 대체 불가능한 인과 결정권(결정/설계/권한 부여/핵심 정보로 사건의 발생과 방향 전환을 좌우하는 권리)과 결산권(핵심 수익/인정이 약속대로 마땅한 사람에게 돌아가는 권리)을 가져야 한다. 모든 일을 주인공이 직접 할 필요는 없다. 조연은 국지적 행동을 실행할 수 있지만 이미 약속된 하이라이트나 수익을 말없이 빼앗아서는 안 된다.
> - **핵심 노드 네 질문**: ① 누가 일이 왜 발생했는지, 어떻게 진입했는지를 결정하는가? ② 누가 대체 불가능한 핵심 선택을 하는가? ③ 누가 핵심 결과를 감당하거나 선택하는가? ④ 핵심 수익·인정·권력은 최종적으로 누구에게 돌아가는가?
> - 전체 규칙은 메인 대화에서 이미 로드한 `references/reader-contract-and-progression.md`를 따른다. 이곳의 내용은 `story-architect`에게 제공하는 축약본일 뿐이며, agent 자체는 해당 파일을 배포받지 않으므로 직접 읽을 수 없다.

### Phase 2: 핵심 설정

Phase 1에서 확정한 목표 감정에서 출발해 장르 틀에 맞는 플롯 패턴을 찾고, 대조 도서에서 재사용 가능한 모듈을 추출한다(구체적인 인물은 기능 슬롯으로 본다). 그런 다음 사용자의 인물과 설정으로 채운다.

다음 핵심 요소를 사용자가 확정하도록 돕는다.

```
## 핵심 설정표

### 기본 정보
- 책 제목: {暂定名}
- 장르/유형: {主类型 + 副类型}
- 목표 플랫폼: {起点/番茄/晋江/其他}
- 예상 분량: {X} 만 자
- 목표 독자: {画像}
- 독자 계약: {本书承诺的核心阅读快感；参 reader-contract-and-progression.md}
- 주인공 하이라이트/대리권: {主角不可替代的判断、选择或贡献}
- 핵심 기대 부채: {开篇必须偿还的承诺}

### 한 문장 줄거리
{주인공 + 목표 + 장애물 + 반전으로 전 작품을 한 문장에 요약}

### 주인공 설정
- 이름: {}
- 나이: {}
- 핵심 특질: {핵심어 2-3개}
- 금손/핵심 능력: {}
- 약점/결함: {인물을 입체적으로 만드는 부분}
- 핵심 동기: {그가 이 일을 하는 이유}

### 세계관 골격
- 시대/배경: {}
- 핵심 설정: {동종 작품과 구별되는 독특한 설정}
- 힘의 체계: {있다면 간단히 요약}
- 사회 구조: {이야기에 영향을 미치는 핵심 설정}

### 핵심 갈등
- 주 갈등: {}
- 최종 보스/최종 장애물: {}
```

핵심 설정을 완성한 뒤 다음 artifact를 만든다([references/artifact-protocols.md](artifact-protocols.md)의 해당 템플릿을 로드한다).
- **设定/关系.md**: 인물 관계 매핑(character-relations.md의 “네 가지 관계 유형” 참조)
- **设定/题材定位.md**: 장르 핵심 콘셉트 3분법과 대조 분석(genre-core-mechanics.md의 “핵심 콘셉트 해석” 참조). 대조 분석표에는 2-3줄 요약만 남기고 상세 데이터는 `对标/` 디렉터리에 둔다.
- **设定/题材正文提示卡.md**: `设定/题材定位.md` + `references/genre-prose-cards.md`(색인) + `references/genre-prose-cards/`(장르별 본문 카드 디렉터리) + `references/style-genre-modules.md`(범용 장르 보충)에서 이 책의 본문용 장르 카드를 추출한다. 장르 경계, 핵심 논리, 독자 기대, 핵심 쾌감/감정, 본문 적용점, 초·중·후반 운영, 리듬 밀도, 장면 입자, 이탈 금지만 기록하고, 범용 형식 규칙은 쓰지 않으며 `设定/文风.md`를 덮어쓰지 않는다.

> **대조 도서가 여러 권일 때**: `references/cross-book-recall.md`를 참조하고, 보조 대조 도서의 anchor는 “대조 분석” 표 부록에 넣는다.

#### Agent 호출: story-architect + character-designer

#### 세부 개요(전 작품의 각 장)

⚠️ **개요 안전 7검(배치 단위 필수 답변)**: 각 권 또는 각 배치의 세부 개요를 설계하기 전에 전체 질문에 한 번 답한다. 장별 설계에서는 ⑥⑦만 다시 답하고 위험 등급을 해당 장 세부 개요의 “계약 위험” 행에 기록한다. 장마다 전체 표를 반복해 답하지 않는다. 중간에 플롯 단위를 추가할 때 ⑦의 핵심 장면 앵커는 단위 안에서 1/4·중점·3/4 기준으로 실행하며, 이미 잠근 권 규모 좌표표는 바꾸지 않는다.

① 이 권은 어떤 감정을 전달하는가? 그것을 안정적으로 전달할 수 있는 플롯 패턴은 무엇인가? ② 이 권의 핵심 갈등은 무엇인가? ③ 권의 리듬(기승전결)에서 어느 부분을 가속하고 어느 부분을 감속할 것인가? ④ 이 권에서 새로 심어야 할 복선은 무엇인가? 전 권에서 회수하지 못한 복선은 어떻게 처리할 것인가? ⑤ 장의 기능 분포에 고저가 있는가(처음부터 끝까지 고압이 아님)? 저압+전환 장의 비율을 절제했는가(합계 약 15% 이하)? ⑥ 이 권/이 장은 전 작품의 어느 단계에 있으며 무엇을 공개할 수 있고 무엇을 눌러 두어야 하는가? ⑦ 독자 계약, 주인공 대리권, 기대 부채, 최종 국면 비축(최종 비장의 카드/승급 단계)을 `reader-contract-and-progression.md` 기준으로 계약 안전/보강 필요/계약 파괴 중 무엇으로 평가할 것인가? 대조 도서가 있다면 1/4·중점·3/4에 각각 핵심 장면을 하나씩 앵커링했는가(`references/outline-structure-theory.md`의 “장 기능과 완급/대조 리듬 이식” 참조)?

**개요 안전 심사(순서를 뒤집지 않음)**: 배치 단위로 한 번 실행하며 해당 배치의 모든 플롯 단위와 장을 포괄한다. 먼저 `references/emotional-methods.md`에 따라 긍정적 감정 엔진과 장르 핵심 약속을 설계한 뒤, 권위 파일의 주인공 대리권/소유권/성장 관련 부정적 위험 방어선으로 진단한다. 인과 결정권과 결산권, 핵심 노드 네 질문, 기대 소유권에 따라 각 플롯 단위의 주인공 목표, 핵심 선택, 약속 이행의 귀속, 핵심 자산 교환, 기관/세력의 경계, 환승 부채와 진행선을 점검한다. 모든 행동을 주인공이 직접 실행할 필요는 없다. 계약 파괴는 반드시 개요를 고치고, 보강 필요는 교환·복선·비용을 보완한다. 이어 반증 가능한 두 가지 퇴화 점검을 한다. ① 장르 핵심의 대상/관계/문제를 제거하면 일반적인 직업 승급물이나 껍데기만 바꾼 줄거리로 퇴화하는가? ② 주인공을 제거해도 감정의 약속이 거의 변하지 않는가? 하나라도 “예”라면 먼저 엔진을 고친다.

**모든 장에는 반드시 세부 개요 파일 하나가 있어야 한다**(`大纲/细纲_第XXX章.md`). 장을 건너뛰어서는 안 된다.

기본적으로 개요는 배치별로 작성한다. 먼저 앞 10장의 세부 개요를 만든 뒤 **정박**하고 “제1장 집필/일일 연재를 시작할 수 있습니다”라고 보고한다. 사용자가 본문 집필을 명시적으로 요구할 때만 Phase 4로 들어간다. 롤링 보충 개요는 번호 규칙에 따라 실행한다(`references/outline-structure-theory.md`의 “플롯 배치별 세부 개요 작성” 참조).

1. **배치 경계**: 한 배치는 대략 하나의 플롯 단위(5-15장)다. 10장을 넘는 플롯 단위는 두 배치로 나눈다. **첫 배치는 앞 10장으로 상한을 두되 플롯 단위를 가로지를 수 있다**. 가로질러 들어간 플롯 단위는 카드를 만들 때 한 번 회수하고, 나머지 장은 이후 롤링 배치가 그 플롯 단위 카드의 결론을 공유한다. 단위 말단에 도달해 아직 세부 개요를 만들지 않은 장이 2장 이하로 남으면 다음 단위 전체를 한 배치로 롤링 보충한다. 사용자가 장 수/범위를 명시하면 그 요구를 따르되 한 배치는 여전히 10장 이하를 권장하고 배치별로 연속 제공한다.
2. **배치 위치와 단계 제약**: 매번 보충 개요를 만들기 전에 현재 장 범위가 어느 단계와 어느 플롯 단위(단위 ID)에 속하는지, 이 배치의 진행 목표, 공개 가능한 정보, 조기 공개를 엄격히 금지하는 정보, 장 끝 훅이 넘어서는 안 되는 경계를 먼저 쓴다.
3. **플롯 단위 소비**: 카드 작성 배치에서는 해당 플롯 단위 카드의 “对标剧情参照”가 가리키는 플롯 단위를 읽는다(최대 3개 파일, 구조 분포/장면 노드 색인 포함). 박자를 장에 매핑해 장을 배치하고, 장면 노드의 소재는 바꾼다. 같은 플롯 단위의 후속 배치는 카드에 고정된 결론을 공유하며 플롯 단위를 다시 읽지 않는다. 현재 권별 개요에 필수 플롯 단위 필드가 없으면 먼저 권별 개요를 보완하고, 필드가 빠진 상태로 일일 연재에 들어가지 않는다.
4. **배치 말미 예산 대조**: 각 배치를 만든 뒤 모든 장의 “예산 합계” 행을 일괄 확인한다. Σ는 `[장 목표, 장 목표×1.1]` 범위에 있어야 한다. 기준을 벗어난 장은 밀도 높은 지점을 보충하거나 성긴 지점을 압축한 뒤 제공하며, 장을 집필할 때마다 반복해서 암산할 필요는 없다.

한 번의 대화에서 30장 분량의 완성된 세부 개요를 억지로 만들지 않는다.
전 작품의 장 수가 적으면(≤30장) Phase 3에서 한 번에 모두 만들 수 있다.

```

### 제 N장: {장명}
- 핵심 사건: {한 문장; 일일 연재와 가져오기에서 공통으로 소비}

- 단계 위치: {도입기/발전기/절정기/마무리기; 제X단계 제Y장; 이 장이 단계에서 맡는 역할}

#### 장면 세부화
- 장면 노드 순서: 글자 수 예산에 따라 배치하며 수량을 거꾸로 계산하지 않는다. 각 장면 노드에 밀도/성김을 표시하고 글자 수 예산을 준다. 밀도 높은 노드(쾌감/망신/반전/감정 절정, 확장 서술)는 250자 이상, 슬로 모션 쾌감은 400-600자다. 성긴 노드(전환/이동/정보 전달, 간단히 처리)는 약 40자다. 복선/일상은 중간값인 약 120-150자로 잡는다. 각 노드 예산의 합 Σ는 `[장 목표, 장 목표×1.1]`에 들어가야 한다. 장 목표보다 낮으면 확장 노드를 늘리고(쾌감 포인트의 세부 박자를 쪼개거나 핵심 노드에 구체적인 사례를 보충), 상한보다 높으면 전환 장면을 압축하거나 성긴 노드를 합친다. 물을 타거나 쾌감 포인트를 끝없이 쌓아 분량을 맞추지 않는다. 노드 수는 Σ가 정해진 뒤 결정한다(보통 10개 이상). 목표가 1500자 미만인 단장은 5-8개 노드를 사용하고 밀도 노드 하한을 목표 비율에 따라 약 120-250자로 낮춘다. 목표가 범위로 주어지면 범위 상한으로 Σ를 계산한다. 장면 세부화 끝에는 Σ 대조를 위해 `预算合计：X字（目标Y，范围Y-Z）` 한 줄을 쓴다. 각 장면 노드에는 “누가 무엇을 했는가 + 기능 태그”를 명시한다. 기능 태그는 목적어(복선/절정/쾌감/망신/인물 형성/설정)이며, 이 장면을 펼칠지 간단히 넘길지를 결정한다. 예를 들어 “주인공이 청구서에서 4,800위안이 빠져나간 것을 발견한다【정보 공개·밀도250】”처럼 쓰며 “발견”이라고만 쓰지 않는다.
- 임무 장애물 설명: 장면 노드가 “일을 처리하다 막힘”이라면 기능 태그에 정보 공개, 관계 변화, 대가 이행, 복선 진행, 선택 압박, 리듬 환기, 훅 연결 중 무엇을 위한 장애물인지 명확히 쓴다. 삭제해도 손실이 없는 장애물은 세부 개요에 넣지 않는다.
- 행동 비용(없어도 됨)/수익 귀속: {행동 비용은 없을 수 있음. 있다면 누가 어떤 비용을 치르는지, 수익이 누구에게 귀속되고 어떻게 드러나는지, 후속 장부가 남는지를 쓴다}

#### 결말 설정과 훅
- 결말 설정: {어떤 구체적인 행동이나 장면으로 수습되는가(“이렇게…” “그는 마침내 깨달았다…” 같은 상태 판정어는 쓰지 않음); 미해결 문제; 다음 장의 추진력}
- 장 끝 훅: {장 끝 13식 중 선택} — {구체적 내용, 기대도: 강/중/약; 저압/전환 장은 약한 훅이나 단계 목표를 남겨도 됨; 다음 장과 어떻게 연결되는지}
```

**개요 잠금**: 본문 집필에 들어간 앞 10장의 세부 개요는 잠그며 사용자 확인 없이 수정하지 않는다. 이후 롤링 세부 개요는 본문 피드백에 따라 미세 조정할 수 있다. **권별 개요 잠금의 정의**: 어느 권이든 본문 장이 하나라도 생기면, 그 권에서 이미 작성된 구간에 대응하는 기존 플롯 단위 카드와 대조 구조 좌표를 잠긴 것으로 본다. 사용자 확인 없이는 기존 내용을 바꾸지 않지만 권 말미에 새 플롯 단위 카드를 **추가**할 수는 있다(추가만 가능하고 수정은 불가). 이 추가도 사용자가 보충 개요/확장 개요를 명시적으로 요구했을 때만 실행한다. 일일 연재/본문 집필 과정에서는 플롯 단위 카드를 자동으로 추가하지 않는다. `workflow-daily` 곳곳의 “잠긴 권별 개요는 절대 자동 수정하지 않는다”는 이 정의에 따른다.

**중간 보충 개요/확장 개요 절차**(프로젝트에 이미 개요가 있고 사용자가 “세부 개요 작성/보충/다음 구간의 줄거리 계획”을 요구할 때 실행):

1. 현재 권, 집필 완료 진행도, 기존 플롯 단위 카드를 확인한다. `大纲/大纲.md`, 현재 `大纲/卷纲_第X卷.md`, `追踪/上下文.md`(이어쓰기 상태 카드에서 회수할 복선은 `## 活跃伏笔`, 주인공 현재 상태는 `## 核心角色状态`)와 `设定/题材定位.md`(최종 비장의 카드와 승급 단계)를 읽는다. 이어쓰기 상태 카드에 항목이 없으면 `workflow-daily`의 “과거 정보 찾기 단계”에 따라 필요한 부분만 조회하고, 장별 증분을 전부 읽지 않는다.
2. `references/outline-structure-theory.md`의 “대조 리듬 이식” 1단계에 따라 같은 유형의 플롯 단위를 골라 새 플롯 단위 카드(“对标剧情参照” 포함)를 설계한다. 이를 현재 권별 개요의 끝에 **추가**하고, 카드와 함께 권별 개요의 “감정 곡선” 표와 “이 권의 복선” 표에도 해당 계획을 **추가만 하고 기존 내용은 수정하지 않는다**. 아직 실제로 심지 않은 복선은 개요에만 두고 타임라인/추적 사실로 미리 등록하지 않는다. 사용자가 보충 개요를 요구한 것은 추가 권한을 부여한 것으로 보며, 이미 잠긴 기존 플롯 단위 카드는 건드리지 않는다. 새 플롯 단위의 분량이 이 권의 계획을 초과하면 먼저 권을 늘릴지 새 권을 열지 사용자에게 확인한다.
3. 배치 단위로 위의 “개요 안전 7검”에 답하고 “개요 안전 심사”를 실행한다(플롯 단위를 추가할 때 ⑦은 단위 안의 1/4·중점·3/4 기준을 적용한다).
4. “플롯 배치별 세부 개요 작성” 규칙에 따라 새 플롯 단위를 배치로 삼아 세부 개요를 롤링 보충한다(한 배치≈하나의 플롯 단위, 10장을 넘으면 두 배치로 나누고 회수 내용을 공유). 각 배치를 만든 뒤 “세부 개요 후 설정 보완”과 배치 말미 예산 대조를 실행한다.
5. 새 플롯 단위와 미래 공개 경계는 권별 개요/세부 개요에 기록하고 이어쓰기 상태 카드에는 복사하지 않는다. 다음 장에서 반드시 이행해야 하는 약속만 다음 장별 트랜잭션에서 `next_chapter_commitments`에 넣는다.

**세부 개요 품질 요건**: 모든 장의 세부 개요는 현재 장의 청사진에 따라 본문을 직접 안내해야 한다(단계 위치, 구조 공식, 조기 공개 금지, 내용 개요, 줄거리 배치, 인물 관계/등장 순서, 장면 세부화, 결말 설정을 빠짐없이 포함). 단, **강도는 장의 기능에 따라 배분하며 모든 장을 최고 강도로 채우지 않는다**. 고압/진행 장에는 훅·쾌감·서스펜스를 갖추고, 저압/관계/수련/정보 정리 장에는 뚜렷한 쾌감 포인트가 없거나 약한 훅·감정 훅만 있어도 된다. 대신 환기·관계·복선·전환이라는 기능을 분명히 쓴다. 최저선은 모든 장에 독자가 계속 읽을 이유를 하나씩 두고, 인접한 장의 감정이 반복되지 않게 하는 것이다(`references/outline-structure-theory.md`의 “장 기능과 완급” 참조). 필드가 불완전하면 먼저 채운다. 자료로 확인할 수 없는 관계나 보조선은 `[待补充]`로 쓰고 꾸며내지 않는다.

> **세부 개요 훅의 출처**: 우선 이번 배치의 플롯 단위 카드에서 “对标剧情参照”가 가리키는 플롯 단위의 박자와 약속 이행 방식을 따라 훅 사슬을 설계한다. 대조 도서가 여러 권이면 `references/cross-book-recall.md`를 참조하며, 보조 대조 도서의 같은 기조 `章节/*_摘要.md`도 단일 장 훅의 영감으로 선택해 사용할 수 있다.

**장 제목 규칙**: 가볍게 중복만 제거한다. 같은 제목이나 눈에 띄게 비슷한 제목이 발견되면 이 장의 핵심 사건에 맞춰 이름을 바꾸고, 세부 개요 제목과 본문 파일명을 일치시킨다.

**세부 개요 후 설정 보완(각 배치의 세부 개요를 만든 뒤 실행)**: 이번 배치의 세부 개요에 새로 등장한 고유 인물·세력·핵심 설정을 훑는다. 이후 여러 번 등장하거나 줄거리 기능을 맡아 **재사용할 대상**은 사용자 확인을 기다리지 않고 자동으로 기록한다.
- 인물 → `设定/角色/{名}.md` 생성(character-basics.md의 주인공 카드/조연 카드 빈 템플릿 참조). 핵심 재사용 인물이 실제 본문에 등장한 뒤에는 추적 트랜잭션이 `追踪/角色状态/{名}.md` 동적 스냅샷을 만든다.
- 세력/조직 → `设定/势力/{名}.md` 생성(이름, 포지션, 핵심 목표, 핵심 인물, 주인공과의 관계).
- 여러 장에 영향을 미치는 세계관 규칙 → `设定/世界观/{主题}.md` 생성 또는 보완(규칙, 적용 범위).

이미 존재하는 설정 파일은 세부 개요의 새 정보에 따라 **증분 보완하고 덮어쓰지 않는다**. 일회성 행인이나 후반에 역할이 없는 조연은 정적 설정 파일이나 동적 스냅샷을 만들지 않는다. 설정 파일에는 세부 개요에서 확정된 정보만 쓰고, 미정 필드는 자리표시자로 남기며 미리 꾸며내지 않는다.

개요를 완성한 뒤 다음 artifact를 만든다([references/artifact-protocols.md](artifact-protocols.md)의 해당 템플릿을 로드한다).
- **大纲/大纲.md**: 전 작품의 권별 조감도(권명+분량+장 수+핵심 사건+상태 변화, 단락형 요약)
- **大纲/卷纲_第X卷.md**: 각 권의 플롯 단위+감정 곡선(장 기능 포함)+인물 곡선+복선+반전+대조 구조 좌표(`outline-methods.md`의 “개요 3층 구조법” + `outline-structure-theory.md`의 “장 기능과 완급/대조 리듬 이식” + `emotional-arc-design.md`의 “6가지 곡선 빠른 참조” + `reversal-toolkit.md`의 “반전 유형” 참조)
- **추적 트랜잭션 초기 상태**: `references/tracking-transaction.md`에 따라 0장 초기화 JSON을 만들고 `scripts/tracking_commit.py init`을 실행한다. 체크포인트, 이어쓰기 상태 카드(고정 7개 섹션), 빈 복선/타임라인 뷰와 디렉터리를 생성한다. 핵심 인물의 동적 스냅샷은 첫 본문 트랜잭션에서 만들 수 있다.

#### Agent 호출: story-architect

개요 구축 단계에서는 우선 메인 대화에서 권별 개요와 첫 배치의 세부 개요를 만든다. 구조가 복잡하거나 반전 사슬이 많거나 메인 대화의 설계가 불안정할 때만 `story-architect` agent를 호출한다.

`story-architect` agent가 배포되어 있다면(`.claude/agents/story-architect.md`를 우선 확인) 다음을 보조하게 할 수 있다.
- 임무: 권별 구조, 첫 배치 세부 개요, 훅/반전/감정 곡선.
- 장 기능: 각 장에 고압/진행/수련 시행착오/관계 회수/저압 일상/정보 정리를 표시한다. 저압 장도 약한 쾌감 포인트는 허용하지만 독자가 계속 읽을 이유는 있어야 한다.
- 글자 수 예산: 각 장면 노드에 밀도/성김과 예산을 표시한다. 밀도 높은 노드는 펼치고 성긴 노드는 간단히 처리하며, 끝에 `预算合计：X字（目标Y，范围Y-Z）`를 쓴다.
- 메인 대화 검증: 모든 장면 노드에 예산이 있고 합계가 `[장 목표, 장 목표×1.1]`에 들어오는지 확인한다. 기준을 벗어나면 먼저 세부 개요를 보완한 뒤 본문을 쓴다.
- **계약 요약은 반드시 원문 그대로 첨부**: 이 단계의 권별 개요는 최종 국면 비축(이 권의 주 추진선/전과, 이 권에서 해금할 최종 국면 이정표, 건드리지 않을 미해금 비장의 카드)과 플롯 단위(단위 ID 등 필드)를 직접 산출해야 한다. spawn prompt에는 Phase 1의 “Agent 호출: story-architect”에 있는 “story-architect 계약 요약”을 반드시 포함해 메인 스레드와 위임 산출물이 같은 schema를 사용하게 한다.

agent를 사용할 수 없으면 메인 스레드가 직접 실행한다.
