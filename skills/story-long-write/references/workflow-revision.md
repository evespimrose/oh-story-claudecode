# workflow-revision.md: 대수정 워크플로

이 문서는 “대수정/재작업” 상황에 대한 전체 지침이다. SKILL.md가 이 문서로 라우팅한 뒤에는 아래 절차에 따라 실행한다.

---

## 적용 조건

- 사용자가 “제X장 수정”, “제X장 재작업”, “제X장 다시 쓰기”라고 말한 경우
- 목표: 이미 작성된 장 내용을 수정

> 사용자는 반드시 장 번호 또는 장 제목을 지정해야 한다. 어느 장을 수정해야 하는지 자동으로 추론할 수 없다.

---

## Step 1: 장 위치 확인

1. “제X장”을 기준으로 파일을 찾는다: `正文/第{X}章_*.md`
2. 사용자가 번호가 아니라 장 제목을 말한 경우, `find 正文/ -name "*{关键词}*"`로 검색한다
3. 찾을 수 없으면 사용자에게 구체적인 장을 확인해 달라고 요청한다
4. 사용자가 단락 범위(“제3-5단락”/“그 전투 장면”/“대화 부분”)를 지정했다면, 국부 수정 대상으로 기록한다

---

## Step 2: 컨텍스트 로드

일상적인 집필보다 더 많은 컨텍스트를 로드한다(수정에는 앞뒤 연결을 이해해야 하기 때문).

| 번호 | 파일 | 용도 | 없는 경우 |
|------|------|------|-----------|
| 1 | `正文/第{X}章_*.md` | 수정 대상 장 | 반드시 존재해야 함 |
| 2 | `大纲/细纲_第{X}章.md` | 원래 집필 계획 | 건너뜀 |
| 3 | `正文/第{X-1}章_*.md` | 이전 장(연결) | 제1장일 때는 `设定/世界观/背景设定.md`를 대신 로드 |
| 4 | `正文/第{X+1}章_*.md` | 다음 장(연결) | 마지막 장일 때는 `大纲/细纲_第{X+1}章.md`(있는 경우)를 확인해 연속성 확보 |
| 5 | `tracking_commit.py check` + `追踪/上下文.md` | 도구로 유일한 state와 파생 뷰가 일치하는지 확인한다. 이어쓰기 상태 카드는 현재 연속성을 제공하며, 전체 state를 prompt에 넣지 않는다 | state가 없으면 중지. 이미 본문이 있는 프로젝트는 반드시 `story-import`를 통해 표준 추적 상태를 생성해야 함 |
| 6 | `设定/角色/{相关角色}.md` + `追踪/角色状态/{相关角色}.md` | 정적 인물 설정 + 동적 현재 스냅샷 | 동적 스냅샷이 없으면 관련 증분에서 재계산 |

**관련 인물 판정**: `大纲/细纲_第{X}章.md`에서 인물명을 추출한다. 세부 개요가 없으면 수정 대상 장 본문에서 `设定/角色/` 디렉터리 아래의 인물명 키워드를 검색한다. 인물명을 파일명으로 매핑한다: `设定/角色/{角色名}.md`.

---

## Step 3: 수정

1. **원문 읽기**: 장 전체 내용을 읽고 원래 글자 수를 기록한다
2. **원문 백업**: 원문을 `正文/第{X}章_章名_原稿_{YYYYMMDD}.md`로 복사해 되돌릴 수 있게 한다
3. **수정 범위 확인**: 사용자에게 “전체 다시 쓰기”인지 “특정 단락 수정”인지 묻는다
   - 전체 다시 쓰기: 세부 개요를 바탕으로 다시 쓰고, 백업은 유지한다
   - 국부 수정: 지정된 단락만 수정한다(장면 번호 또는 키워드로 위치 확인). 나머지 부분은 그대로 유지한다
4. **수정 실행**: 파일을 고쳐 쓴다
5. **글자 수 비교**: 수정 후 원문과의 글자 수 차이가 30% 초과 또는 800자 초과일 때 사용자에게 알린다(더 큰 값을 기준으로 함)

**자료 조사(필요 시)**: 수정에 검증이 필요한 외부 사실(역사 연대, 지리적 방위, 직업 관련 세부 사항 등)이 포함된 경우, `story-researcher` agent를 spawn해 검색·검증한다.

---

## Step 4: 연쇄 점검

수정 완료 후, 한 번의 `mode=revision` 추적 트랜잭션으로 연쇄 업데이트를 완료한다. 프로토콜은 [tracking-transaction.md](tracking-transaction.md)를 참조한다.

1. **수정 장 증분 재계산**: 기존 본문/기존 증분과 새 본문을 비교하고, 새 버전에서 미래에도 여전히 유효한 `result / 角色变化 / 伏笔变化 / 时间与揭示 / 约束 / 下一章承诺`만 보존한다. 트랜잭션 도구는 `追踪/逐章记录/第{X}章.md` 전체를 다시 쓰며, 새 본문에 의해 뒤집힌 결론은 보존하지 않는다.
2. **복선 현재값**: 영향을 받는 ID에 대해 제X장부터 마지막으로 작성된 장 M까지 점검하고, 수정 후의 **M장 기준 현재 상태**를 제출한다. 수정으로 매설이 삭제되었지만 이후 본문에서 해당 ID를 계속 참조한다면, 먼저 본문 충돌로 나열해야 하며 단순 삭제해서는 안 된다. 해당 라인 전체가 존재하지 않는다고 확정될 때만 `action=delete`를 사용한다. `伏笔.md`는 항상 ID당 한 줄이며, 수정 이력을 추가하지 않는다.
3. **시간과 독자 인지**: 영향을 받는 사건에 대해 객관적 사실, M장 기준 독자의 현재 인지, 실제 공개 상태/장을 제출한다. 삭제된 사건은 `action=delete`를 사용한다. 미래 공개 계획은 계속 개요에 둔다. 도구는 사건을 `_tracking-state.json`에 병합하고 작가/독자 뷰를 재구성하며, 각각을 수동으로 따로 수정하는 것을 금지한다.
4. **인물 현재 스냅샷**: 영향을 받는 핵심 인물에 대해 X부터 M까지 점검하고, 신분, 위치, 목표, 능력·자원, 관계 대상, 알려진 정보, 미해결 사항별로 재계산해 M장 기준의 완전한 스냅샷 하나를 제출한다. 마지막 단일 차원의 변화 하나로 다른 차원을 덮어써서는 안 된다.
5. **가져오기 마감 범위**: X ≤ `_tracking-state.json.imported_through_chapter`인 경우, 트랜잭션은 제X장에 새 덮어쓰기 기록을 추가한다. 가져오기 마감 장은 변하지 않으며, 현재 구조화 상태는 수정 결과에 따라 업데이트된다.
6. **제출과 재시도**: 수정 시작 시 `tracking_commit.py check`가 반환한 `state_revision`을 `expected_state_revision`에 쓴 다음 `tracking_commit.py commit`을 실행한다. 그 사이 상태가 변경되었다면 현재 상태를 다시 읽고 트랜잭션을 재구성한다. 어느 단계든 실패하면 원래 트랜잭션 JSON을 보존하고, 쓰기 환경을 수정한 뒤 동일한 `commit`을 다시 실행한다. 성공하고 `check`를 통과하기 전에는 다음 장을 계속 수정하거나 새 장을 쓰는 것을 금지한다.
7. **후속 영향**: 수정이 인물 상태/관계/세계관 설정을 바꾸는 경우, 후속 장 본문을 스캔해 영향을 받는 항목을 표시한다.

```
⚠️ 제{X}장 수정 후 다음 장을 동기화해야 할 수 있습니다:
- 제{X+1}장: {原因}(점검 권장)
- 제{X+3}장: {原因}(점검 권장)
```

8. **본문 메타 정보 스캔**: 제목 줄 이외에 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 같은 집필 공정 용어가 섞여 있는지 확인하고, 발견되면 인물이 그 시점에 인지할 수 있는 사건 앵커 또는 상대적 시간으로 바꾼다. 이야기 안에서 실제로 “제X장”을 읽거나 논의하는 경우, 또는 실제 독자 신분 맥락은 예외로 한다
9. **금지어 스캔**: `references/banned-words.md`와 대조해 수정 후 내용을 점검하고, `tracking_commit.py check`를 실행해 state와 모든 파생 뷰가 일치하는지 검증한다

---

## Step 5: 품질 점검

수정 후 장에 대해 Phase 5 품질 점검을 실행한다(최소 포함 항목).

1. **금지어 스캔**: Step 4에서 장 전체를 다루지 않았다면 다시 스캔한다
2. **본문 메타 정보 스캔**: 「연쇄 점검」의 「본문 메타 정보 스캔」과 동일하게, 장 전체가 포함되었는지 확인한다.
3. **인물 일관성**: 수정 후 인물 행동이 인물 설정과 일치하는지 확인한다
4. **리듬 점검**: 수정이 장의 리듬을 망가뜨렸는지 확인한다

> 전체 점검 목록은 [Phase 5: 품질 점검](../SKILL.md#phase-5质量检查)을 참조한다.

## 자주 묻는 문제

| 문제 | 처리 |
|------|------|
| 사용자가 어디를 고칠지 말하지 않음 | “어느 장을 고치고 싶으신가요? 어느 측면인가요? 줄거리/리듬/대화/묘사?”라고 묻는다 |
| 수정 후 글자 수가 크게 증가/감소 | 사용자에게 알리고, 조정 여부는 사용자가 결정하게 한다 |
| 여러 장을 연속으로 수정 | 장별로 수정하며, 각 장마다 Step 2-5를 독립적으로 실행한다 |
| 수정 후 후속 내용이 일치하지 않음을 발견 | 영향을 받는 장을 나열하고, 지금 수정할지 사용자가 결정하게 한다 |
