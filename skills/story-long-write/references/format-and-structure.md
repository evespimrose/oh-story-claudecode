# 본문 형식과 장면 구조

> 작성 전 필독 사항입니다. 다음 형식은 현재 저장소에서 약정한 기본 본문 전달 형식입니다. 사용자나 목표 플랫폼에 명확한 요구사항이 있을 경우, 사용자/플랫폼의 요구사항을 우선으로 합니다.
>
> **적용 범위**: 단락 형식(드라마 단위/쇼트 우선, 짧은 단락이 기본, 긴 단락은 완전한 추론·분위기·감정 흐름용)과 대사 형식은 모든 장르에 적용됩니다. 장면(beat) 구조와 글자 수 기준은 단편에만 적용됩니다. 장편소설의 글자 수는 본 장의 상세 개요의 `글자 수 목표`와 통일된 90% 최소 기준을 따릅니다.

---

## 장 표시

기본 형식(유연성 순):

| 형식 | 플랫폼 적용 | 예시 |
|------|----------|------|
| `###1.` | 단편 기본값 | `###1.` `###2.` `###3.` |
| `###제1장` | 일부 플랫폼 | `###제1장` `###제2장` |
| `1.`(순수 숫자) | 지후 | `1.` `2.` `3.`(### 접두사 없음) |

**규칙**: 전체 글에서 한 가지 형식으로 통일하며, 혼용하지 마세요. 단편은 `###1.` 또는 순수 숫자를 권장하며, 간결하고 효율적입니다.

---

## 단락 형식

### 핵심 규칙: 드라마 단위 우선

기본 배판 방식은 **드라마 단위/쇼트별로 자연스럽게 단락을 나누고, 단락을 촘촘히 배열**합니다. 정해진 글자 수를 강제 절단의 기준으로 삼지 마세요. 먼저 "한 가지 사건/하나의 추리 연쇄/하나의 정서 변화"가 완성되었는지 판단하세요.

- 한 단락은 하나의 드라마 단위를 담습니다: 하나의 행동 연쇄, 하나의 단서 발견, 한 번의 시선 전환, 한 차례의 심리 판단, 또는 연속된 분위기/추리/정서 흐름.
- 장면 종료, 한 가지 사건 종료, 새로운 행동, 새로운 사물, 새로운 정보, 새로운 대사는 새로운 단락에서 시작합니다. 같은 순간에 발생하는 일, 지각, 반응은 함께 엮어야 하며, 행동층/지각층/반응층으로 나누지 마세요.
- 본문의 인접한 단락 사이에는 **줄바꿈 `\n` 한 개만 허용**되며, 빈 줄이나 연속 줄바꿈 `\n\n`은 나타나면 안 됩니다(긴밀한 배치).
- 들여쓰기 없음(플랫폼 렌더러가 자동으로 처리하므로 `　　` 또는 공백이 필요 없음).
- 길이는 진단 목적만 고려: 읽을 때 답답하거나, 여러 음절이 섞여 있거나, 휴대폰 화면에서 읽기 어려울 때만 나눔; 완전한 추론, 분위기 조성, 감정 전개가 미완성일 때는 연결성을 유지하기 위해 다소 긴 단락을 허용합니다.

### 단락 리듬(길이 교차 + 밀도 차별화)

짧은 단락의 빠른 읽기는 웹소설 휴대폰 읽기의 기본이며, 긴 단락은 완전한 추론, 분위기, 감정 침전을 담당합니다. **전체 단락의 길이가 같으면 안 되며**, 모든 단락을 동일한 글자 수 기준으로 자르면 안 됩니다:

- **길이의 변화**：클라이맥스, 반전, 반전은 최대한 짧게（한 문장이 한 단락）；추리 연쇄, 환경의 압박, 감정의 침전, 장 마무리는 길게 유지하여 독자가 완전한 변화를 읽을 수 있도록 합니다.
- **밀도의 변화（상세함과 간략함）**：재미있는 장면, 전환 beat는 촘촘히（감각, 동작, 세부묘사로 가득）；넘어가는 부분, 연결 beat는 성글게（1-2문장으로 처리, 균등하게 힘 주지 않음）. 모든 beat가 같은 길이, 같은 세밀함이면 AI 문투의 원인이 됩니다.
- **과도한 단편화 금지**：연속된 여러 극단 문단이 같은 장면/같은 사건에 속하면 자연스러운 단락으로 병합하여 개요나 시처럼 보이지 않도록 합니다.

### 주어와 역할 이름의 리듬

역할 이름을 일괄 생략하지 말고, 매 문장마다 명시하지도 마세요. "주어 재설정"에 따라 사용하세요：

- 문단의 시작, 장면 전환, 여러 인물이 같은 장소에 있거나 주어가 혼동될 수 있을 때는 주인공/등장인물명으로 시점을 확립하세요.
- 같은 문단이나 같은 행동 연쇄 내에서는 대명사, 행동 연결, 합리적인 생략을 섞어 쓰되, 모든 문장을 같은 인물명으로 시작하는 것을 피하세요.
- 중요한 전환, 감정의 절정, 신분의 반전이나 독자가 주인공에게 다시 주목해야 할 때는 다시 인물명을 명시해 강조할 수 있습니다.
- 주어 리듬을 검토할 때 "읽기에 끊기는지"를 확인하되, 전체 장에서의 출현 횟수로 일괄 판단하지 마세요. 연속된 문장/연속된 문단이 주어 리셋 없이 같은 인물명을 반복할 때만 주어 과다라고 판단하세요.

## 대사 형식

### 대화 표식

목표 플랫폼/사용자 요구에 따라 선택하세요. 미지정 시 기본 형식을 사용합니다:

| 우선순위 | 형식 | 적용 플랫폼 |
|--------|------|----------|
| 1순위 | `"말하는 내용"` | 단편 기본값, 토마토 |
| 플랫폼/프로젝트 지정 | `「말하는 내용」` | 지후 소금말 단편, 일부 고대 판타지, 일식 또는 사용자 지정 |

**기본값은 `""`**; 사용자나 플랫폼이 따옴표 스타일을 지정할 때는 `「」`로 변경하며, `「」`을 오류로 간주하지 마세요.

### 대사 규칙

1. 대사는 **독립된 행**으로 표기하며, 서술 단락에 포함시키지 않습니다
2. 대사 태그는 필요에 따라: 높은 빈도나 공식화된 「그가 말했다」「그녀가 말했다」「그가 웃으며 말했다」는 동작 묘사로 대체; 일반적인 「말했다」는 낮은 빈도로 사용 가능 (「8가지 절대 금지 사항」 중 「대사 태그 기계화 방지」와 일치)
3. 두 사람의 대사가 연속으로 나타날 때는 태그를 생략하고 내용으로 화자를 구분합니다

**올바른 예시**：
```
그녀가 컵을 내려놓았다.
"가세요."
그는 움직이지 않았다.
"내가 말하는 거야, 가세요."
```

**역시 허용됨（일반적으로 「말했다」의 저빈도 사용）**：
```
그녀는 컵을 내려놓았다.
"가봐."라고 그녀가 말했다.
그는 움직이지 않았다.
"내가 말해, 가봐."
```

**오류 예시**：
```
그녀는 컵을 내려놓으며 말했다: "가세요." 그는 움직이지 않았고, 그녀가 다시 말했다: "내가 말이야, 가세요."
```

## 어조 문장부호 체계

문장부호는 어조, 인물의 음성과 감정 리듬을 표현하는 역할을 하므로, 전체를 마침표로 끝내서도 안 되고 "다양성"을 위해 임의로 기호를 쌓아서도 안 됩니다. 먼저 현재 문장의 기능을 판단한 후 문장부호를 선택하세요:

| 어조 / 기능 | 문장부호 전략 | 방어선 |
|---|---|---|
| 억압 / 침착 / 절제 | 짧은 문장, 쉼표, 마침표, 필요시 콜론으로 판단의 초점을 강조 | 느낌표를 자의로 추가하지 말 것; 절제란 모든 문장에 마침표를 붙이는 것이 아님 |
| 질문 / 탐색 / 반문 | 물음표 + 짧은 추격 구간, 동작 멈춤과 함께 | 모든 문장이 `？`로 끝나는 것을 피할 것 |
| 놀람 / 폭발 / 반전 | 진정한 폭발점은 느낌표 1개 사용 가능, 연속 폭발은 최대 1-2곳 | `!!!`, 전체 단락의 외침식 느낌표 금지 |
| 망설임 / 삼킴 / 미완성 | 쉼표, 마침표, 짧은 문장 끊김, 동작 beat | `……`로 멈춤을 만들지 말 것; 동작과 문장 길이 변화를 우선 사용 |
| 말이 끊김 / 음 끌기 | `——` 사용 금지; 동작 끊김, 줄바꿈, 짧은 문장 또는 미완성 동작으로 대체 | 본문과 대사 모두 `——` / `—` / `--` 금지 |
| 정보 공개 / 낙점 판단 | 콜론, 세미콜론 또는 단문 단락으로 낙점 생성 | 모바일 독서 친화적 유지, 논문식 세미콜론 연쇄 금지 |

실행 규칙:
- 대사 작성 시 먼저 역할 관계와 권력 위치 확인: 강한 역할은 짧은 문장으로 마무리, 탐색적 역할은 물음표와 반문 많이 사용, 붕괴된 역할만 소량의 감탄/생략 허용.
- 서술 작성 시 문장 길이, 쉼표 정지 및 단문 단락으로 리듬 생성; 대시를 리듬 도구로 사용 금지, 대사에서도 사용 금지.
- 정밀 수정 시 두 가지 문제 확인: **전체 마침표화**(어조 전체 압평됨)와 **무작위 문장 부호 쌓임**(물음표/감탄호가 감정 기능 미담당, 또는 줄임표/대시로 억지로 정지 생성).
- 인용부호 스타일은 프로젝트/플랫폼 규약에 따릅니다. 지후 염언의 `「」`은 합법적인 대화 형식이며, `quote-mode keep` 시에는 임의로 변경하면 안 됩니다.

## 소절(beat) 구조

### 기본 규칙

- 숫자 번호(`1` `2` `3`)로 소절을 구분하며, 각 소절은 완전한 서사 beat입니다.
- 각 소절 800-1500자(쾌감형 콘텐츠는 500-800자/절로 압축 가능, genre-writing-formulas.md 참고)
- 8-15개 소절로 전체 텍스트를 다룸 (목표 글자 수에서 역산; 8000÷1000≈8절, 12000÷800≈15절)
- 각 소절은 명확한 하나의 플롯 포인트를 전개함

### 소절 내부 구조

각 소절에는 다음이 포함되어야 함:

1. **하나의 주요 사건** + **3-5개의 부사건** (주요 사건은 핵심 플롯을 전개하고, 부사건은 층차를 풍부하게 함; 초안이 짧을 때는 먼저 소절/세부 구성안으로 돌아가 계획된 부사건, 대사 또는 갈등을 보충한 후 본문을 작성하고, AI 특유의 표현을 제거할 때는 기존 본문에 새로운 플롯을 추가할 수 없음)
2. **하나의 감정 변화**(독자의 감정이 어떻게 변하는지)
3. **독자가 새로 알게 된 정보 한 가지**
4. **3-5 라운드의 대화 교감**(관계 드러내기/갈등 심화, writing-craft.md의 대화 권력 게임 참고. 혼자 발견하기/일기 읽기 같은 특정 장면은 0으로 표시 가능, 현재 skill의 상세 개요/설계 과제 요구사항에 따라 실행)
5. **각 소사건의 삼 차원을 융합**: 발생+지각+반응을 같은 단락 본문에 융합(writing-craft.md의 장면 표현법 참고)


### 소절 간 연결

- 소절 마지막에 훅을 하나 남겨두기(서스펜스/미해결 감정/새로운 질문)
- 다음 절 시작 시 빠르게 이어가기, 다시 설명하지 않기
- 감정의 절 간 상승: 각 절의 감정 강도 ≥ 이전 절. 예외: 피크 감정(반전절) 후 1절은 유지 허용, 하지만 급락은 불허

## 플랫폼 대화 형식 커버 테이블

| 플랫폼 | 장절 마크 | 대화 형식 | 특수 요구사항 |
|------|----------|----------|----------|
| 지후 소금말 | `1.` | `「」` | 도입부는 별도로 표시 필요 |
| 토마토 | `###제1장` | `""` | 첫 단락은 흥미로워야 함 |
| 빨간 과일 | `###1.` | `""` | 없음 |

**통용 원칙**: 사용자가 플랫폼을 지정하지 않을 때는 단편 통용 형식(`###1.` + `""`)을 기본값으로 사용합니다. 사용자 또는 플랫폼에서 염언 스타일을 지정할 때는 `「」`이 허용됩니다.

## 8가지 절대 금지사항

아래 규칙은 글쓰기 전 과정에서 실행되며, 주제나 스타일에 따라 변하지 않습니다.

1. **기계적 글자 수 분단 금지**: 글자 수가 일정 수를 초과한다고 해서 강제로 나누지 마세요. 먼저 단락이 완전한 드라마 단위인지 판단하세요. 여러 동작/정보/시선 전환이 섞여 있을 때만 나누고, 완전한 추론·분위기·감정의 연결은 더 긴 단락으로 보존할 수 있습니다.
2. **단락 간 공백행 금지**: 본문의 인접한 단락 사이에는 줄바꿈 `\n` 하나만 허용되며, 공백행이나 연속 줄바꿈 `\n\n`은 나타나면 안 됩니다.
3. **대사 태그 기계화 회피**: 빈번하거나 공식화된 「그가 말했다」「그녀가 말했다」「그가 웃으며 말했다」는 동작이나 맥락으로 대체하세요. 일반적인 "말했다"는 유지할 수 있습니다.
4. **들여쓰기 금지**: `　　`(전각 공백) 또는 반각 공백으로 들여쓰지 마세요.
5. **본문 단락에서 Markdown 렌더링 금지**: 통일된 소절/장 표시(예: `###1.`)를 제외하고, 본문 단락에서는 굵게 `**`, 기울임 `*`, 제목 `#`, 구분선 `---` 등의 Markdown 문법을 사용하지 마세요.
