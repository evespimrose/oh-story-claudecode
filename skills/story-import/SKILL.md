# story-import: 기존 소설 역방향 가져오기

당신은 소설 프로젝트 역공학 엔지니어입니다. 가져오기는 분량에 따라 분류됩니다: 장편은 Phase 3-L, 단편은 Phase 3-S로 진행합니다.

**산출물은 집필 프로젝트입니다**: 작가가 이미 작성한 책을 이어쓸 수 있는 **집필 프로젝트**(프로젝트 구조 + 분석 자산)로 재구축합니다. `분석라이브러리/{가져올도서명}/`은 프로젝트 재구축의 데이터 소스이며, 사용 후 버리는 중간 산출물이 아니고 산출물 자체를 대체할 수 없습니다. 실행 시 「프로젝트 구축」을 눈에 보이는 목표로 삼으며, 「작품 분석」을 최종 목적이나 대외 라벨로 삼지 마세요.

---

> Agent 호환성: 전문 agent 사용 가능 여부를 확인할 때 `.claude/agents/{agent}.md` → `.opencode/agents/{agent}.md` → `.codex/agents/{agent}.toml` 순서로 찾습니다. Codex 네이티브 서브에이전트 호출은 동명의 `agent_type`을 우선 사용합니다. 현재 Codex 런타임이 `unknown agent_type`을 반환하거나 custom-agent registry를 노출하지 않으면 solo/direct로 다운그레이드해야 합니다. `.zcode/`가 감지되면 ZCode 3.3.4는 프로젝트 custom agent를 실행하지 않으므로 즉시 solo/direct로 전환하며, `Fallback: project custom agents unavailable -> solo`를 보고합니다. Claude/OpenCode 호환용 `subagent_type`을 유지합니다.
>
> Spawn 버전 알림 (spawn 차단 없음): 먼저 프로젝트 루트 `.story-deployed`의 `agents_version`을 읽습니다. 본 버전 `agents_version: 24`와 불일치할 때(표시 누락, 필드 누락/비정수, 24보다 작거나 큰 경우) **파일 존재 여부 확인 후 정상적으로 spawn**하면서 `Notice: agents bundle 버전 불일치 (프로젝트 {N}, 본 버전 24)`를 보고하고 `/story-setup` 재실행 후 새 세션 열기를 안내합니다. 24보다 큰 경우 oh-story-claudecode를 먼저 업데이트하라고 추가 안내하며, 로컬 구버전 setup으로 다운그레이드 덮어쓰기를 하지 않습니다. agent 파일이 없거나 런타임에서 custom agent를 노출하지 않을 때만 solo/direct로 대체하며, `Fallback: ... -> solo`를 보고합니다.

## 핵심 원칙

### 용어 및 디렉토리 경계 (전체 프로세스 하드 제약)

- `{가져올도서명}`: 사용자가 직접 쓰다 말았거나 완결하여 프로젝트로 재구축하려는 소설. 분석 원천은 `분석라이브러리/{가져올도서명}/`으로 고정됩니다.
- `{타겟도서명}`: 사용자가 별도로 선택한 외부 참고 작품. 독립 분석 산출물이어야 하며 원천은 `분석라이브러리/{타겟도서명}/`으로 고정되고, 이번 가져오기 원천을 가리킬 수 없습니다.
- `story-import`는 분석 파이프라인을 재사용하여 `{가져올도서명}`을 분석할 수 있지만, **`{가져올도서명}`을 주/부 타겟으로 등록하거나 `분석라이브러리/{가져올도서명}/` 또는 프로젝트 `설정/`을 `타겟/`에 복사하면 안 됩니다**.
- 사용자가 외부 타겟을 명확히 선택하지 않은 경우, 타겟 하위 디렉토리를 생성하지 않고 `주타겟도서`를 작성하지 않으며, 이후 story-long-write / story-short-write의 타겟 발견 절차에서 별도로 처리합니다.

### 원칙 1: 분석 후 이관

먼저 분석 파이프라인으로 소설을 완벽히 분석한 후(`분석라이브러리/{가져올도서명}/`에 출력), 분석 결과를 프로젝트 구조로 이관합니다. 해당 디렉토리는 본 도서의 가져오기 분석 결과를 보존하며 파기하지 않으나, 외부 타겟 뷰에는 속하지 않습니다.

### 원칙 2: 재사용하며 중복하지 않음

심층 분석 단계에서는 기존 분석 파이프라인을 호출하며 재발명하지 않습니다: 장편은 `/story-long-analyze`의 전체 파이프라인을 실행하고, 단편은 `/story-short-analyze` 파이프라인을 실행합니다. 분석 방법론과 출력 템플릿은 해당 analyze skill에 포함되어 있으며, story-import는 분석 방법론을 직접 실행하거나 관련 파일을 유지보수하지 않습니다.

## Phase 1: 가져오기 원천 확인

### Step 1: 가져오기/이어쓰기 입구 순서 (프로세스 질문 우선 답변)

사용자가 "가져오기 이어쓰기 시 story-setup이 먼저인가 story-import가 먼저인가", "기존 소설은 어떻게 이어쓰는가" 등의 프로세스 관련 질문을 하면 결론을 먼저 답변한 후 원문을 수집합니다:

1. **권장 순서**: 먼저 `/story-setup`(hooks/agents/AGENTS 배포), 세션 새로 열기/새로고침 후 `/story-import` 실행, 마지막으로 `/story-long-write 일일 연재/N장 집필`로 이어쓰기.
2. **직접 `/story-import` 실행도 가능**: 본 skill은 심층 분석 진입 전 `.story-deployed` 및 전문 agent를 감지합니다. 미배포 시 "setup 먼저 진행" 또는 "가져오기 계속(직렬 다운그레이드)" 중 선택지를 제시합니다.
3. **이미 가져온 현재 프로토콜 프로젝트** (도서명 디렉토리 내 `추적/_tracking-state.json` 존재): 전체 가져오기를 중복 실행하지 말고, 도서명 디렉토리로 진입하여 `.active-book`이 올바른 책을 가리키는지 확인한 후 `/story-long-write 일일 연재` 또는 `/story-long-write N장 집필`을 사용합니다.
4. **v0.7.2 이하의 구형 추적 프로젝트** (`추적/`과 본문은 있으나 `추적/_tracking-state.json`이 없는 경우): 일일 연재가 멈추고 재가져오기를 요청하지만, **전체 책 분석을 다시 할 필요는 없습니다**. `추적/`만 재구축하면 됩니다.

질문: **「어떤 책을 가져오시겠습니까? 파일 경로를 제공하시거나 텍스트를 직접 붙여넣어 주세요.」**

## Phase 2: 심층 분석

Phase 1에서 판정된 분량 유형에 따라 해당 analyze skill의 **전체 분석 파이프라인**을 호출합니다.

| 분량 | 호출할 분석 파이프라인 | 산출물 디렉토리 |
|------|--------------|---------|
| 장편 | story-long-analyze 전체 파이프라인 (Stage 0-6) | `분석라이브러리/{가져올도서명}/` |
| 단편 | story-short-analyze 분석 파이프라인 (Stage 2-6) | `분석라이브러리/{가져올도서명}/` |

## Phase 3: 구조 이관

`분석라이브러리/{가져올도서명}/`의 분석 결과를 집필 skill에서 소비할 수 있는 프로젝트 구조로 이관합니다.

### Phase 3-L: 장편 구조 이관

`분석라이브러리/{가져올도서명}/`을 `{가져올도서명}/` 장편 프로젝트 구조로 이관합니다.

```
{가져올도서명}/
├── 설정/
│   ├── 세계관/
│   ├── 캐릭터/
│   └── 세력/
├── 개요/
├── 본문/
├── 추적/
│   └── 장별기록/
├── 타겟/                        # 선택사항: 외부 타겟 명시적 바인딩시에만 생성
└── 참고자료/
```

### Phase 3-S: 단편 구조 이관

```
{단편제목}/
├── 설정.md               ← 핵심 프레임워크 + 본서 이어쓰기 베이스라인
├── 소절개요.md           ← 단락-소절 구조 역산
├── 본문.md               ← 단일 파일 전체 본문
└── 타겟/{타겟도서명}/    ← 선택사항: 외부 타겟 참조 뷰
```

---

## Phase 4: 프로젝트 활성화

- `.active-book`이 가져온 도서명/제목 디렉토리를 가리키도록 설정합니다.
- 프로젝트가 해당 집필 skill (장편 → story-long-write, 단편 → story-short-write)에 의해 인식될 수 있는지 확인합니다.
