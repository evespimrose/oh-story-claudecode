# 본문 형식과 비트(beat) 구조

> 집필 전 필독. 아래 형식은 현 저장소에서 약정한 기본 본문 납품 형식이며, 사용자 또는 목표 플랫폼에 명시적인 요구가 있을 경우 사용자/플랫폼 요구로 우선 덮어쓴다.
>
> **적용 범위**: 문단 형식(극적 단위/샷 우선, 짧은 문단을 기조로, 긴 문단은 완전한 추리·분위기와 감정 호응에 사용)과 대화 형식은 모든 장르에 적용된다. 비트(beat) 구조와 글자 수 기준은 오직 단편에만 적용된다. 장편 소설 글자 수는 금번 세부 개요의 `글자 수 목표`와 통일 90% 통과 하한을 기준으로 한다.

---

## 챕터 표기

기본 형식(유연도 순 정렬):

| 형식 | 플랫폼 적용 | 예시 |
|------|----------|------|
| `###1.` | 단편 기본 | `###1.` `###2.` `###3.` |
| `###첫 번째 장` | 일부 플랫폼 | `###첫 번째 장` `###두 번째 장` |
| `1.`(순수 숫자) | Zhihu | `1.` `2.` `3.`(### 접두사 없음) |

**규칙**: 전문 한 가지 형식으로 통일, 혼용 금지. 단편은 `###1.` 또는 순수 숫자 권장, 간결하고 효율적임.

## 문단 형식

### 핵심 규칙: 극적 단위 우선

기본 납품 조판은 **극적 단위/샷 단위로 자연스럽게 문단을 나누고, 문단을 촘촘히 배열**한다. 고정 글자 수를 강제 절단 칼로 삼지 말 것; 먼저 "한 가지 일/한 개 추리 고리/한 번의 감정 변화"가 완성되었는지 판단한다.

- 한 문단은 한 개의 극적 단위를 담는다: 한 개의 동작 고리, 한 개의 단서 발견, 한 번의 시선 전환, 한 차례의 심리 판단, 또는 한 줄기의 연속된 분위기/추리/감정 고리.
- 장면 종료, 한 가지 일 마감, 새 동작, 새 소품, 새 정보, 새 대화는 별도 문단으로 시작; 동일 순간의 발생, 지각, 반응은 한데 엮어야 하며, 동작층/지각층/반응층으로 쪼개지 않는다.
- 본문 인접 문단 사이에는 **오직 한 개의 개행 문자 `\n`만 허용**하며, 공백 행이나 연속 개행 `\n\n`이 나타나서는 안 됩니다(촘촘한 배열).
- 들여쓰기 없음(플랫폼 렌더러가 자체 처리하므로 `　　` 또는 스페이스 불필요).
- 길이는 오직 진단 용도로만 사용: 읽을 때 답답하거나 여러 개의 비트가 섞여 있거나 휴대폰 화면에서 따라 읽기 어려울 때만 나눕니다. 완전한 추리, 분위기 고조, 감정 고조가 끝나지 않았을 때는 약간 긴 문단으로 연속성을 유지하는 것을 허용합니다.

### 문단 리듬(장단 교차 + 밀도의 구별)

짧은 문단은 속독이 가능하여 웹소설 휴대폰 독서의 기조이고, 긴 문단은 완전한 추리, 분위기와 감정 침전을 담당합니다. **전편 동일 길이 금기**, 또한 매 문단을 동일 글자 수 임계값으로 절단하는 것도 금기입니다:

- **장단 교차**: 클라이맥스, 반전, 급전개는 최소한으로 압축(한 문장의 단락)하고; 추리 과정, 환경 묘사, 감정 축적, 챕터 종료는 비교적 긴 단락을 유지하여 독자가 한 번의 완전한 변화를 경험하게 한다.
- **밀도 구분(상략)**: 쾌감 포인트, 전환 장면은 촘촘히 쓰고(지각, 동작, 디테일을 빈틈없이 채움); 경과, 연결 장면은 드물게 쓴다(1-2문장으로 넘어가고, 평균적으로 힘을 덜 씀). 모든 장면이 같은 길이에 같은 수준의 세밀함을 갖는 것이 바로 AI 스타일의 근원이다.
- **과도한 단편화 금지**: 연속된 여러 극단적으로 짧은 단락이 여전히 같은 장면/같은 사건에 속한다면, 자연스러운 단락으로 병합해야 하며, 개요나 리스트처럼 보이는 것을 피한다.

### 주어와 캐릭터명 리듬

캐릭터명을 무조건 생략하지도 말고, 매 문장마다 명시하지도 말 것. "주어 재설정" 기준으로 사용한다:

- 단락 시작, 장면 전환, 다중 인물 등장, 또는 주어가 혼동될 수 있을 때, 주인공명/캐릭터명으로 시점을 확립한다.
- 동일 문단 또는 동일 동작 흐름 내에서는 대명사, 동작 계승과 합리적 생략을 우선하여 혼용하되, 매 문장마다 동일 캐릭터명으로 시작하는 것을 피한다.
- 핵심 전환, 감정 폭발점, 신분 반전 또는 독자가 다시 주인공에게 주의를 기울여야 할 때는 다시 한 번 지목하여 강조할 수 있다.
- 주어 리듬 검수는 "읽을 때 말을 더듬는지"를 보는 것이지, 전체 장에서의 출현 횟수로 일률적으로 자르지 않는다. 오직 연속 문장/연속 문단에서 주어 재설정 없이 반복적으로 지목된 경우에만 주어 과밀로 간주한다.

## 대화 형식

### 대화 표기

목표 플랫폼/사용자 요구에 따라 선택. 지정되지 않았을 때 기본 형식 사용:

| 우선순위 | 형식 | 적용 플랫폼 |
|--------|------|----------|
| 선호 | `"말 내용"` | 단편 기본, 톡톡(Toutiao) |
| 플랫폼/프로젝트 지정 | `「말 내용」` | Zhihu Yanyan 단편, 일부 고대 로맨스, 일본식 또는 사용자 지정 |

**기본은 `""` 사용**; 사용자 또는 플랫폼에서 옌옌 스타일로 지정 시 `「」`로 변경, `「」`를 오류로 간주하지 말 것.

### 대화 규칙

1. 대화는 **독립 행으로**, 서술 문단에 삽입하지 않는다
2. 대화 태그는 필요에 따라: 고빈도 또는 공식화된 「그가 말했다」「그녀가 말했다」「그가 웃으며 말했다」는 동작 묘사로 대체; 일반적인 「말했다」는 저빈도 사용 시 유지 가능 (「8가지 절대 금지」중 「대화 태그 기계화 피하기」항목과 일치)
3. 두 사람 대화가 연속될 때, 태그를 생략하고 내용으로 화자를 구분한다

**올바른 예시**:
```
그녀가 잔을 내려놓았다.
"가세요."
그는 움직이지 않았다.
"내가 말하는데, 가세요."
```

**합법（일반적으로 「말했다」를 저빈도로 사용）**：
```
그녀가 컵을 내려놓았다.
"가세요."라고 그녀가 말했다.
그는 움직이지 않았다.
"내가 말하는데, 가세요."
```

**잘못된 예시**:
```
그녀가 잔을 내려놓으며 말했다. "당신 가세요." 그는 움직이지 않았고, 그녀가 다시 말했다. "내가 말이야, 당신 가세요."
```

## 어조 문장 부호 계보

문장 부호는 톤, 인물의 성격과 감정의 리듬을 표현하기 위해 사용되어야 하며, 문단 전체를 마침표로 끝내거나 "풍부하게" 보이도록 임의로 기호를 쌓아 올려서는 안 된다. 먼저 현재 문장의 기능을 판단한 후 문장 부호를 선택하세요:

| 어조 / 기능 | 문장 부호 전략 | 방어선 |
|---|---|---|
| 압박 / 냉정 / 절제 | 짧은 문장, 쉼표, 마침표, 필요 시 콜론으로 강조를 더한다 | 의도적으로 느낌표를 추가하지 말 것; 절제는 매 문장마다 마침표를 찍는 것이 아님 |
| 질문 / 시험 / 반문 | 물음표 + 짧고 빠른 추궁 파편, 동작 일시 정지와 배합 | 매 문장을 `？`로 끝내는 것 피하기 |
| 놀람 / 폭발 / 깨달음 | 진정한 폭발점은 느낌표 1개 사용 가능, 연속 폭발은 최대 1-2군데 | `!!!` 금지, 전 단락 고함식 감탄 금지 |
| 망설임 / 삼킴 / 미완결 | 쉼표, 마침표, 짧은 문장으로 끊기, 동작 beat | `……` 으로 일시 정지 만들지 말 것; 우선 동작과 문장 길이 변화 사용 |
| 막힘 / 길게 늘여 소리 내기 | `——` 사용하지 않음; 대신 동작으로 끊기, 개행, 짧은 문장 또는 미완료 동작 사용 | 본문과 대화 모두 `——` / `—` / `--` 금지 |
| 정보 계시 / 판단 낙하점 | 콜론, 세미콜론 또는 한 문장으로 된 문단으로 낙하점 제작 | 모바일 독서 친화 유지, 논문식 세미콜론 나열 쓰지 말 것 |

실행 규칙:
- 대화를 쓸 때 먼저 캐릭터 관계와 권력 위치를 보세요: 강세 캐릭터는 종종 짧은 문장으로 마무리하고, 시험 캐릭터는 물음표와 반절 문장이 많으며, 붕괴 캐릭터만 소량의 감탄/생략을 허용합니다.
- 서술을 쓸 때는 문장 길이, 쉼표 일시 정지와 한 문장 문단으로 리듬을 만드세요. 대시를 리듬 도구로 삼지 말고, 대화 안에서도 사용하지 마세요.
- 정교한 수정 시 두 가지 문제를 검사하세요: **전편 마침표화**(어조가 전부 눌려 평탄해짐)와 **무작위 문장 부호 누적**(물음표/느낌표가 감정 기능을 담지 않거나, 말줄임표/대시로 억지로 일시 정지를 만듦).
- 인용부호 스타일은 프로젝트/플랫폼 약정에 따릅니다. 지후 옌옌의 `「」`은 합법적인 대화 형식이며, `quote-mode keep` 시 임의로 고쳐서는 안 됩니다.

## 비트(beat) 구조

### 기본 규칙

- 숫자 번호(`1` `2` `3`)로 비트를 분할하며, 각 비트는 완전한 서사 beat입니다
- 매 비트 800-1500 글자(사물 소설은 500-800 글자/비트로 압축 가능, genre-writing-formulas.md 참고)
- 8-15개의 비트로 전문을 커버(목표 글자 수로 역산; 8000÷1000≈8비트, 12000÷800≈15비트)
- 매 비트마다 명확한 플롯 포인트를 한 개씩 추진

### 비트 내부 구조

각 비트는 다음을 포함해야 합니다:

1. **한 개의 주사건** + **3-5개의 부사건**(주사건은 핵심 플롯을 추진하고, 부사건은 층위를 풍부하게 함; 초고가 짧을 때는 먼저 비트/세부 개요로 돌아가 계획 내 부사건, 대화 또는 충돌을 보충한 후 본문을 작성; AI 냄새 제거 시 기존 본문이 있을 때는 신규 플롯 추가 금지)
2. **한 번의 감정 변화**(독자의 감상이 어떻게 변화하는가)
3. **한 줄기의 독자가 새로 알게 되는 정보**
4. **3-5 차례의 대화 교전**(관계 계시/충돌 고도화, writing-craft.md 대화 권력 투쟁 참고. 단독 발견/일지 열람 등 특정 장면은 0으로 표기 가능, 현재 skill의 세부 개요/설계 업무 요구에 따라 집행)
5. **각 부사건 3차원 녹여넣기**: 발생+지각+반응을 동일한 단락의 본문에 녹여 넣기(writing-craft.md 장면 쓰기 참고)


### 비트 간 접속

- 비트 끝에 갈고리(현안/미해결 감정/새 문제)를 하나 남긴다
- 다음 비트 시작은 빠르게 계속, 다시 기초를 다지지 말 것
- 감정의 비트 간 고조: 매 비트의 감정 강도 ≥ 상위 비트. 예외: 피크 감정(반전 비트) 후 1비트간 유지하여 하락하지 않는 것은 허용하나, 급강하는 허용하지 않는다

## 플랫폼 대화 형식 커버 표

| 플랫폼 | 챕터 표기 | 대화 형식 | 특수 요구 |
|------|----------|----------|----------|
| 지후 옌옌 | `1.` | `「」` | 서두는 별도 표기 필요 |
| 톡톡 | `###첫 번째 장` | `""` | 첫 단락은 흡인력 필요 |
| 홍과(红果) | `###1.` | `""` | 없음 |

**통용 원칙**: 사용자가 플랫폼을 지정하지 않았을 때, 기본적으로 단편 통용 형식(`###1.` + `""`) 사용; 사용자 또는 플랫폼에서 옌옌 스타일로 지정 시, `「」`는 허용된다.

## 8가지 절대 금지

다음 규칙은 집필 전 과정에 적용되며, 장르나 스타일에 관계없이 변하지 않습니다:

1. **글자 수에 따른 기계적 문단 분할 금지**: 어떤 글자 수를 초과했다는 이유로 강제 분할하지 않습니다. 먼저 문단이 여전히 완전한 극적 단위인지 판단합니다. 여러 개의 동작/정보/시선 전환이 섞여 있을 때만 분할하며, 완전한 추리, 분위기, 감정 호흡은 다소 긴 문단으로 유지할 수 있습니다.
2. **문단 간 공백 행 금지**: 본문에서 인접한 문단 사이에는 오직 하나의 개행 문자 `\n`만 허용되며, 공백 행이나 연속 개행 `\n\n`이 나타나서는 안 됩니다.
3. **대화 태그 기계화 피하기**: 빈번하거나 공식화된 「그가 말했다」「그녀가 말했다」「그가 웃으며 말했다」 같은 표현은 동작/문맥으로 대체합니다. 일반적인 「말하다」는 유지할 수 있습니다.
4. **들여쓰기 금지**: `　　`(전각 스페이스) 또는 반각 스페이스 들여쓰기를 사용하지 않습니다.
5. **본문 문단 Markdown 렌더링 금지**：통일된 비트/챕터 표기（예：`###1.`）외에 본문 문단에서 볼드 `**`、이탤릭 `*`、제목 `#`、구분선 `---` 등 Markdown 문법을 사용하지 않는다
6. **본문에 대시 사용 금지**：본문（서술、대화、심리 묘사 포함）에 대시 `——`/`—` 또는 쌍반각 하이픈 `--` 를 사용하지 않으며 대신 마침표、쉼표、개행、동작 beat 또는 짧은 문장으로 끊기；더 이상"대화 예외"를 설정하지 않는다
7. **전편 마침표화 또는 무작위 문장 부호 누적 금지**：문장 부호는 반드시 어조/인물 성향/감정 기능과 매치되어야 한다；마땅히 추궁할 때는 물음표，마땅히 폭발할 때는 소량의 감탄부호；망설임、삼킴、미완결은 동작 또는 문장 길이 변화로 표현하며 `……` / `——` 로 억지로 일시 정지를 만들지 말고 기능 없이 `？`/`！` 를 함부로 뿌려서도 안 된다
8. **본문에 챕터 메타 정보 혼입 금지**：챕터 번호는 오직 제목/비트 표기/파일명/추적 기록에만 출현이 허용된다. 본문 서술、대화、심리 묘사 안에 `第[一二三四五六七八九十백천만양0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 류의 집필 공정 단어가 나타나서는 안 된다；캐릭터가 지각 가능한 사건 앵커 또는 상대 시간으로 고쳐야 하며 예를 들어"그 3초 발화보다 더 아팠다"를"그 3초 발화보다 더 아팠다"로 고친다. 예외：캐릭터가 스토리 월드 내에서 진정으로"제X장" 텍스트를 열람/토론하거나 진정으로 작가/독자 신분으로서 독자 신분을 논할 때 해당 단어를 유지할 수 있다.
