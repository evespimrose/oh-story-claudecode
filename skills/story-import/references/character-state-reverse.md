# 핵심 캐릭터 현 시점 스냅샷 역추적 규칙（장편 임포트）

> 오직 `story-import` 로 장편을 임포트할 때만 사용. 출력은 계속 추가하는 캐릭터 히스토리가 아니라，초기화 트랜잭션 내의 `character_snapshots` 이다；`tracking_commit.py init` 이 각 핵심 캐릭터마다 `추적/캐릭터 상태/{캐릭터명}.md` 를 생성한다.

## 一、입력 소스

이미 디스크에 저장된 작품 분석（拆文）산출물로만 역추적，`원문/` 를 다시 읽지 않음：

| 입력 | 용도 |
|---|---|
| `拆文库/{书名}/角色/{角色名}.md` | 신분、능력、목표、성장 아크、출현 기록 |
| `拆文库/{书名}/角色/角色关系.md` | 마지막 완전 챕터까지의 핵심 관계 |
| `拆文库/{书名}/章节/第N章_摘要.md` | 마지막 위치、최신 상태、기지 정보와 미결 사항 |
| `拆文库/{书名}/剧情/*.md` | 진영/신분 전환、단계 목표와 장기 충돌 |
| 초기화 트랜잭션 중인 복선과 타임라인 후보 | 캐릭터 미결 사항과 그 알 수 있는 범위 대조 |

## 二、추적 대상

오직 주인공、반역자、핵심 조연에만 독립 스냅샷을 작성. 임시 행인과 한 번만 기능을 맡는 캐릭터는 파일을 만들지 않는다. 경계가 불분명할 때는 만들지 않는 것을 우선，이후 캐릭터가 진정으로 재사용 상태에 들어갔을 때 장별 트랜잭션에서 다시 작성한다.

## 三、역추적 방법

각 핵심 캐릭터마다，마지막 완전 임포트 챕터 N 을 단면으로 삼아，각각 다음을 확정：

1. `identity`：N 챕터까지 실제로 성립된 신분/직업，미래 승진 계획은 쓰지 않음.
2. `location`：마지막 낙하지점 또는 다음 챕터 시작 전에 확정 가능한 위치.
3. `goal`：캐릭터가 현재 추구하고 있는 구체적인 목표.
4. `state`：신체、감정、명망、입장 중 속행에 영향을 미칠 현 상태；필요한 정보만 작성.
5. `abilities_resources`：현재 확실히 습득한 능력、물품、권한、작품 또는 인맥，최대 8줄.
6. `relationships`：이후 재사용될 캐릭터와의 현재 관계，최대 8줄.
7. `knowledge`：캐릭터 본인이 이미 알고 있으며，그의 행동에 영향을 미칠 정보，최대 8줄. 작가만 아는 진상을 캐릭터 기지로 오인해 쓰지 말 것.
8. `open_threads`：캐릭터 관련 미결 사항，최대 8줄；반드시 이미 작성된 본문 증거가 있어야 하며，순수 미래 설계는 개요（大纲）에 남긴다.

동일 필드에 여러 차례 변화가 있더라도，N 챕터까지의 현재 값만 취하며，변화사를 스냅샷에 욱여넣지 않는다. 히스토리 변화는 이후 `장별 기록/第NNN章.md` 가 담당；구 챕터 임포트 시 이러한 기록들을 보충 제작하지 않는다.

## 四、초기화 JSON 형상

이하 예시는 demo 《让你管账号，你高燃混剪炸全网》第 10 챕터에서 가져옴：

```json
{
  "江晨": {
    "identity": "火箭军文工团宣传兵；军宣爆款创作者",
    "location": "火箭军文工团高层看片会",
    "goal": "完成五天百万粉任务，继续做出真正能打的军宣内容",
    "state": "专业团队重拍版反向坐实手机原版的价值，军内认可继续抬升",
    "abilities_resources": [
      "前世 MCN 爆款运营经验",
      "《中国军魂》伴奏",
      "大师级导演能力"
    ],
    "relationships": [
      "钟嘉嘉持续提供军报资源",
      "周薄森和张耀祖已明确认可其创作能力"
    ],
    "knowledge": [
      "《军报》采访稿已经过审",
      "高层决定继续采用《诸君，且听龙吟》手机原版"
    ],
    "open_threads": [
      "五天百万粉任务尚未结算",
      "钟嘉嘉所谓只猜对一半仍未解释"
    ]
  }
}
```

도구가 이에 따라 생성하는 파일은 고정적으로 포함：챕터 기준、신분、위치、현재 목표、심신 상태、능력과 자원、핵심 관계、기지 정보、미결 사항. 모델은 별도로 Markdown 템플릿을 새로 작성해서는 안 된다.

## 五、잔여 원고와 배치 임포트

- 마지막 챕터가 잔여 원고：모든 스냅샷은 잔여 원고 이전의 마지막 완전 챕터까지；잔여 원고 중의 동작、획득물、관계 변화는 사전에 효력 발생시키지 않음.
- 배치 임포트：스냅샷은 오직 금번 이미 임포트한 범위의 현재 상태만 표시；임포트 범위를 확장할 때는 완전 임포트를 한 번 더 재실행，구 스냅샷에 히스토리 단락을 추가하지 않음.

## 六、품질 검사

- [ ] 각 파일은 한 명의 핵심 캐릭터에 대응，무기능 캐릭터 적재 없음
- [ ] 모든 필드는 마지막 완전 챕터까지의 현재 값
- [ ] 캐릭터 기지 정보에 작가 진상이 혼입되지 않았음
- [ ] 미결 사항에는 모두 본문 증거가 있으며，미래 설계는 여전히 개요에 남아 있음
- [ ] 단일 캐릭터 스냅샷 목표는 4096 바이트를 초과하지 않음；부득이 필요하면 완화 가능하나，8192 바이트 하드 상한을 초과해서는 안 됨
- [ ] `tracking_commit.py check` 통과
