# 핵심 캐릭터 현 시점 스냅샷 역추적 규칙 (장편 임포트)

> 오직 `story-import`로 장편을 임포트할 때만 사용합니다. 출력물은 계속해서 추가되는 캐릭터 히스토리가 아니라, 초기화 트랜잭션 내의 `character_snapshots`입니다. `tracking_commit.py init`이 각 핵심 캐릭터마다 `추적/캐릭터 상태/{캐릭터명}.md`를 생성합니다.

## 1. 입력 소스

이미 디스크에 저장된 작품 분석 결과물로만 역추적하며, `원문/`을 다시 읽지 않습니다.

| 입력 | 용도 |
|---|---|
| `작품분석고/{도서명}/캐릭터/{캐릭터명}.md` | 신분, 능력, 목표, 성장 아크, 등장 기록 |
| `문고 해체/{책 제목}/캐릭터/캐릭터_관계.md` | 마지막 완료 챕터까지의 핵심 관계 |
| `문고 해체/{책 제목}/챕터/제N장_요약.md` | 마지막 위치, 최신 상태, 기지 정보 및 미결 사항 |
| `문고 해체/{책 제목}/스토리/*.md` | 진영/신분 전환, 단계별 목표 및 장기적 갈등 |
| 초기화 트랜잭션 중인 복선과 타임라인 후보 | 캐릭터 미결 사항과 그 알 수 있는 범위 대조 |

## 2. 추적 대상

오직 주인공, 반역자, 핵심 조연에 대해서만 독립 스냅샷을 작성한다. 임시 엑스트라나 일회성 캐릭터는 파일을 생성하지 않는다. 경계가 모호할 때는 생성하지 않는 것을 원칙으로 하며, 이후 캐릭터가 실제로 재사용되는 시점에 챕터별 트랜잭션에서 다시 작성한다.

## 3. 역추적 방법

각 핵심 캐릭터마다 마지막으로 완전히 임포트된 챕터 N을 기준으로 다음 사항을 확정합니다:

1. `identity`: 챕터 N까지 실제로 확립된 신분/직업(미래 승진 계획은 제외).
2. `location`: 마지막 도착 지점 또는 다음 챕터 시작 전 확정 가능한 위치.
3. `goal`: 캐릭터가 현재 추구하는 구체적인 목표.
4. `state`: 신체, 감정, 명망, 입장 중 전개에 영향을 미칠 현재 상태. 필요한 정보만 작성.
5. `abilities_resources`: 현재 확실히 습득한 능력, 물품, 권한, 작품 또는 인맥. 최대 8줄.
6. `relationships`: 이후 다시 등장할 캐릭터와의 현재 관계. 최대 8줄.
7. `knowledge`: 캐릭터 본인이 이미 알고 있으며 행동에 영향을 미칠 정보. 최대 8줄. 작가만 아는 진상을 캐릭터가 이미 알고 있는 사실로 오해하여 작성하지 말 것.
8. `open_threads`: 캐릭터 관련 미결 사항. 최대 8줄. 반드시 이미 작성된 본문에 근거가 있어야 하며, 순수 미래 설정은 개요에 남길 것.

동일 필드에 여러 차례 변화가 있더라도 N 챕터까지의 현재 값만 취하며, 변경 이력을 스냅샷에 포함하지 않습니다. 히스토리 변경 사항은 이후 `장별 기록/제NNN장.md`에서 담당하며, 이전 챕터 임포트 시 이러한 기록을 별도로 생성하지 않습니다.

## 4. 초기화 JSON 구조

다음 예시는 데모 《계정 관리하랬더니, 하이라이트 영상으로 인터넷을 뒤집어놓음》 제10장에서 가져온 것입니다.

```json
{
  "장천": {
    "identity": "로켓군 문공단 홍보병; 군 홍보 인기 콘텐츠 제작자",
    "location": "로켓군 문공단 고위급 시사회",
    "goal": "5일 내 백만 팔로워 달성 미션 완료 및 진정으로 파급력 있는 군 홍보 콘텐츠 제작 지속",
    "state": "전문 팀의 재촬영 버전이 오히려 원본 모바일 영상의 가치를 입증하며, 군 내부의 인정이 계속해서 상승 중",
    "abilities_resources": [
      "전생의 MCN 히트작 운영 경험",
      "《중국군혼》 반주",
      "마스터급 연출 능력"
    ],
    "relationships": [
      "중자자가 지속적으로 군보 리소스를 제공함",
      "주보썬과 장야오쭈가 창작 능력을 명확히 인정함"
    ],
    "knowledge": [
      "《군보》 인터뷰 원고 심의 통과",
      "고위층에서 《제군들, 용의 포효를 들어라》 모바일 원본을 계속 채택하기로 결정"
    ],
    "open_threads": [
      "5일 내 100만 팔로워 달성 미션 미정산",
      "중가가가 말한 '절반만 맞혔다'는 내용이 여전히 설명되지 않음"
    ]
  }
}
```

도구가 이에 따라 생성하는 파일은 다음 항목을 고정적으로 포함합니다: 챕터 기준, 신분, 위치, 현재 목표, 심신 상태, 능력 및 자원, 핵심 관계, 기지 정보, 미결 사항. 모델은 별도의 Markdown 템플릿을 새로 작성해서는 안 됩니다.

## 5. 잔여 원고 및 일괄 가져오기

- 마지막 챕터가 잔여 원고인 경우: 모든 스냅샷은 잔여 원고 이전의 마지막 완성 챕터까지만 생성하며, 잔여 원고 내의 동작, 획득물, 관계 변화는 미리 반영하지 않습니다.
- 배치 임포트: 스냅샷은 이번에 임포트한 범위의 현재 상태만 표시함. 임포트 범위를 확장할 때는 전체 임포트를 다시 실행하며, 기존 스냅샷에 히스토리 단락을 추가하지 않음.

## 6. 품질 검사

- [ ] 각 파일은 핵심 캐릭터 1명에 대응하며, 기능이 없는 캐릭터는 포함하지 않음
- [ ] 모든 필드는 마지막 완전 챕터까지의 현재 값
- [ ] 캐릭터 기지 정보에 작가 진상이 혼입되지 않았음
- [ ] 미결 사항은 모두 본문에 근거가 있어야 하며, 향후 설계는 개요에 유지함
- [ ] 단일 캐릭터 스냅샷의 목표 크기는 4096바이트를 초과하지 않음. 필요시 완화할 수 있으나, 8192바이트의 하드 제한(Hard Limit)을 초과해서는 안 됨.
- [ ] `tracking_commit.py check` 통과
