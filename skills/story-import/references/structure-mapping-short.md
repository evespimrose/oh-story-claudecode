# 구조 마이그레이션 매핑 규칙(단편)

Phase 3-S 단편 구조 마이그레이션의 상세 매핑 규칙. `拆文库/{임포트할 도서명}/` 단편 拆文 산출물을 `{단편제목}/` 단편 프로젝트 구조로 변환하여 `story-short-write` Phase 3에서 매끄럽게 인수받을 수 있도록 합니다.

> 장편 마이그레이션 규칙은 `structure-mapping-long.md`를 참조하세요.

> **이름 경계**: `{임포트할 도서명}`은 사용자가 직접 작성할 단편이고, `{비교 대상 도서명}`은 별도로 선택한 외부 참고 작품입니다. 본 단편의 拆文 결과를 본 단편의 `비교대상/` 폴더에 복사하면 안 되며, 본 단편의 분석 내용을 "대표 요약"으로 작성하면 안 됩니다.

---

## 장편과의 주요 차이점

| 차원 | 단편 | 장편 |
|------|------|------|
| 본문 | 단일 파일 `본문.md`, **장 구분 없음** | `본문/제XXX장_장명.md` 다중 파일 |
| 추적 디렉토리 | **생성 안 함** `추적/` | 생성 `추적/`(`_tracking-state.json`, 속편 상태 카드, 장별 기록, 캐릭터 스냅샷, 복선 뷰, 이중 시점 타임라인) |
| 캐릭터 상태 | **생성 안 함** 캐릭터 추적 | 핵심 캐릭터별 `추적/캐릭터상태/{캐릭터명}.md` 생성, `character-state-reverse.md`에서 역추적 |
| 대강 체계 | **생성 안 함** 권별 대강, 세부 대강 | `대강/권별대강_제X권.md` + `대강/세부대강_제N장.md` 생성 |
| 대강 디렉토리 | **생성하지 않음** `대강/` 디렉토리 | 생성 |
| 후속 연결 | story-short-write Phase 3(장면별 작성) | story-long-write 일일 업데이트 순환 |

## 매핑 개요

| 책 분해 산물 | 단편 프로젝트 파일 | 변환 방식 |
|---------|------------|---------|
| 원문 전체(`분해문고/{임포트 책명}/원문/`) | `{제목}/본문.md` | 단일 파일 마이그레이션, 아래 『본문.md 형식 규범』에 따라 표준화, 내용 재작성 없음 |
| `분석 보고서.md`의 이야기 핵심/소재/구조 필드 | `{제목}/설정.md`(핵심 프레임워크 영역) | 본서의 핵심 프레임워크를 역으로 추론하며, 보고서에 존재할 수 있는 자체 벤치마킹 기록은 상속하지 않음 |
| `플롯 노드.md`의 기능 분할 | `{제목}/소절 개요.md` | 소절 개요를 역으로 추론(시작 단락/铺垫 단락/심화 단락/반전 단락/결말 단락으로 구성, 훅 필드에 `[대기 중]` 표시) |
| `분석 보고서.md` + `작문 기법.md` | `{제목}/설정.md`(본서 연속 작성 기준선 영역) | 기존 작성 내용의 구조, 감정, 반전 및 현존하는 작문법을 내부 연속 작성 컨텍스트로 정리 |
| `분석 라이브러리/{벤치마크 도서명}/` | `{제목}/벤치마크/{벤치마크 도서명}/` | 선택 항목: 사용자가 명시적으로 바인딩한 외부 참고 작품만 동기화 |

## 설정.md 역추론 규칙

대상 파일은 본 문서에서 정의한 현재 핵심 프레임워크 템플릿을 사용하며, 두 개의 섹션으로 나뉩니다:

### 섹션 1: 핵심 프레임워크

`拆文报告.md`의 이야기 핵심, 구조 분할, 인물 분석 등 필드에서 추출하여 다음 템플릿에 입력하세요:

```markdown
## 단편 핵심 프레임워크

### 기본 정보
- 제목: {임포트할 도서명}
- 목표 글자수: {원문 실제 글자수} 자
- 목표 플랫폼: {뜯어쓰기 보고서에서 추출, 없으면 [보충 필요] 입력}
- 감정 목표: {뜯어쓰기 보고서의 「감정선/폭발점 분석」에서 추출한 독자 기대 감정}

### 한 문장 요약
{주인공 + 곤경 + 반전 + 감정 낙점(분석 보고서 스토리 핵심에서 추출)}

### 핵심 반전
- 반전 유형：{분석 보고서 반전 분석에서 추출: 정체성 반전/관점 반전/동기 반전/타임라인 반전}
- 반전 내용：{한 문장 설명}
- 복선 단서：{플롯 노드 중 「복선」 유형 노드에서 추출, 최소 3개; 부족할 경우 [보충 필요] 표기}

### 감정 설계
- 시작 감정: {감정 곡선의 첫 번째 노드에서 추출}（강도 {1-10}）
- 중간 감정: {중간 감정 노드}（강도 {1-10}）
- 반전 감정: {반전 노드 감정 최고점}（강도 {1-10}）
- 종료 감정: {종료 노드 감정}（강도 {1-10}）

### 인물 특성 스케치
- 주인공: {한 문장 인물 설정, 인물 분석에서 추출}
- 핵심 인물: {한 문장 인물 설정}
- 관계: {그들 간의 관계}
```

> 불확실한 필드는 반드시 `[보충 필요]` 표시를 추가하고, 빈 필드를 남기지 마세요.

### 구간 2: 본서 연속 집필 기준선

`뜯어쓰기 라이브러리/{가져온 책 제목}/뜯어쓰기 보고서.md`와 `집필 기법.md`에서 추출하여, 본서 내부 연속 집필 기준선으로 정리:

```markdown
## 본서 연속 집필 기준선

### 스토리 구조
{구조 분석 보고서의 「기능 분단」 필드에서 추출, 각 단계의 기능 개요}

### 감정 리듬
{감정 곡선/클라이맥스 분석에서 추출, 감정 변화 추세와 피크 위치 설명}

### 핵심 반전 메커니즘
{반전 메커니즘 분석에서 추출, 복선 경로 포함}

### 재사용 가능한 작문 기법
{`작문 기법.md` 또는 분석 보고서 「재사용 가능한 구조」 필드에서 추출, ≥3개}
```

## 소절 개요.md 역추론 규칙

`정절 노드.md`의 기능 분단 구조에서 추출하여 단편 단-소절 구조로 매핑합니다.

### 단계 매핑

| 단편 단명 | 대응 정절 노드 기능 단 | 설명 |
|---------|----------------|------|
| 도입부 | 시작(주인공/배경/어려움 소개) | 보통 1-2개 섹션 |
| 전개부 | 전개 초기(갈등 축적/복선 배치) | 보통 2-4개 섹션 |
| 상승부 | 전개 후기(갈등 심화/오해 심화) | 보통 2-3개 섹션 |
| 반전부 | 절정(핵심 반전 폭발) | 보통 1-2개 섹션, 감정 피크 |
| 결말부 | 결말(마무리/감정 도착점) | 보통 1-2개 섹션 |

### 소절 항목 템플릿

```markdown
## 도입 단락

### 소절 1
- 핵심 이벤트: {플롯 노드에서 해당 섹션의 주요 플롯 포인트를 추출}
- 감정 목표: {감정 곡선 노드에 대응하는 감정 단어}
- 챕터 시작 훅: [추가 예정]
- 챕터 종료 훅: [추가 예정]
- 참고 글자수: {원문 대응 단락 글자수로 추정}
```

> 훅 필드 표시 `[추가 예정]`——안정적으로 추출할 수 없으므로 사용자 또는 계속 작성할 때 입력하도록 남겨둔 것입니다.

### 소절 수량 추산

원문의 실제 글자 수로 추정: `총 글자 수 ÷ 1000 ≈ 소절 수`(단편 참고 범위 8-15개 소절). 소절 수와 정문의 실제 단락 구조 일치 여부는 품질 체크리스트의 필수 검사 항목입니다.

## 정문.md 형식 규범

원문을 단일 파일 `정문.md`로 이전하고, 형식은 `format-and-structure.md` 규범에 따라 표준화합니다:

| 규범 항목 | 요구사항 |
|--------|------|
| 소절 표기 | `###1.` `###2.` `###3.`(단편 공용 형식; 사용자가 플랫폼을 지정할 때 `format-and-structure.md` 플랫폼 커버 테이블에 따라 전환) |
| 단락 구분 | 드라마 단위/장면/사건 완결을 기준으로 자연스럽게 단락을 나누고, 고정 글자 수로 강제 분할하지 않음. 완전한 추론, 분위기, 감정 흐름은 다소 긴 단락으로 유지 가능하며, 전체가 같은 길이이거나 개요처럼 단편화되지 않도록 함 |
| 단락 간 공백 | 본문의 인접한 단락 사이에 **오직 한 개의 줄바꿈 `\n`만 허용**, 공백이나 `\n\n`이 나타나면 안 됨 |
| 대사 인용부호 | 기본값은 `""` 반각 큰따옴표이며, Zhihu 염언 플랫폼에서는 `「」` 사용 가능 |
| 들여쓰기 | 들여쓰기 없음. 전각/반각 공백 사용 금지 |
| Markdown | 본문 단락에서 `**` `*` `#` `---` 등의 Markdown 문법을 사용하지 않음 (소절 제목 표시만 제외) |

**원본 내용은 수정하지 않으며**, 형식만 규범화합니다(문단 구분, 따옴표 통일, 소절 표식 추가).

## 외부 비교 참조 보기(선택 사항)

사용자가 독립적인 외부 `{대조서명}`을 명시적으로 바인딩할 때만, `분할문고/{대조서명}/`을 `{제목}/대조/{대조서명}/`로 복사합니다(skip `_archive_*/`, 아카이브 스냅샷은 대조 보기에 포함되지 않음). 후속 작성 단계에서 로드하기 위해:

```
{제목}/대조/{대조서명}/
├── 원문/
├── 분해문 보고서.md
├── 줄거리 노드.md
├── 작성 기법.md
└── _meta.json
```

이 보기는 선택사항이며, 외부 대조본이 없을 때는 만들지 않습니다. 복사하기 전에 반드시 출처가 `분해문라이브러리/{대조서명}/`인지 확인하고, `분해문라이브러리/{가져오기서명}/` 또는 현재 `설정.md`를 사용해서는 안 됩니다.

## 품질 검사 체크리스트

Phase 3-S 마이그레이션 완료 후 실행:

- [ ] `정문.md` 단일 파일이 존재하며 형식이 `format-and-structure.md`를 준수함(소절 마크, 단락 구분/주어 리듬, 단락 간 단일 줄바꿈만 사용, 인용부호 형식)
- [ ] `설정.md`에 핵심 프레임워크 블록 + 본서 속편 작성 기준 블록이 포함되어 있으며, 핵심 프레임워크가 본 파일 템플릿을 준수함
- [ ] `소절 대강.md`의 절 수가 정문의 실제 단락 구조와 일치함
- [ ] 모든 `[추가 예정]` 마크가 추가되었음(불확실한 필드는 공백으로 두지 않음)
- [ ] `추적/`, `대강/`, `정문/` 등 장편 전용 디렉터리가 잘못 만들어지지 않았는지 확인
- [ ] `拆文库/{导入书名}/`이 현재 `대표/`로 복사되지 않았는지 확인; 외부 대표를 바인딩한 경우, 출처와 `대표/{대표서명}/` 디렉터리명이 일치하는지 확인
