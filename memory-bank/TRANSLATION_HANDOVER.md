# 중국어→한국어 현지화 작업 인계 보고서

> **작성 목적:** 이 문서는 다음 세션이 현재 번역 작업의 실제 적용 상태, 미완료 범위, 안전 제약 및 재개 절차를 빠짐없이 파악하도록 작성한 인계 기록이다. 번역을 재개하기 전에 반드시 프로젝트 루트의 [`TRANSLATION_TODO.md`](../TRANSLATION_TODO.md)를 다시 읽고, 이 문서와 상충하는 지시가 있으면 사용자에게 확인한다.

## 1. 최우선 결론

현재 세션은 **프로젝트 일반 파일 61개와 `demo/` 파일 9개를 번역하여 적용**했으나, 전수 검수와 전체 현지화는 완료하지 못했다. 자동 현지화 처리 환경이 작업 중 간헐적으로 빈 응답을 반환해 대량 처리를 안정적으로 이어 가지 못했다. 따라서 현재 프로젝트는 **번역 중간 상태**이며, 완료로 간주해서는 안 된다.

특히 `TRANSLATION_TODO.md`에는 다음과 같은 상위 작업 제약이 있다.

> `demo/`는 파일 내용 절대 건드리지 말 것. 이름만 변경.

그러나 이번 세션에서는 사용자의 직접 요청을 좇는 과정에서 `demo/` 파일 **9개의 본문을 변경**했다. 다음 세션은 이 충돌을 반드시 인지하고, **추가 demo 본문 번역을 즉시 중단**해야 한다. 사용자가 명시적으로 `TRANSLATION_TODO.md`의 제약을 변경·폐기한다고 확인하지 않는 한, 해당 9개 변경을 유지할지 되돌릴지도 사용자에게 먼저 확인하는 것이 안전하다.

## 3. 이번 세션에서 실제 적용된 번역

변경 없는 원문 해시와 현재 Git 상태를 확인한 뒤 **61개 파일**을 적용했다. 이 집합에는 `README.md`, 여러 `scripts/`, 그리고 여러 `skills/*` 문서·스크립트가 포함된다. 적용 전 원문 SHA-256을 대조했으므로 당시 사용자 변경과의 직접 충돌은 확인되지 않았다.

다만 아래 사항 때문에 이 61개는 아직 최종 승인본이 아니다.

## 4. 자동 현지화 시도와 중단 사유

프로젝트 문서·코드 구조를 보존하기 위해 중국어가 들어간 줄 단위로 현지화하는 방식을 사용했다. 대표 문서에는 자연스러운 한국어 현지화가 적용되었지만, 장문·대량 요청에서 아래 오류가 반복됐다.

| 문제 | 관찰된 현상 | 재개 시 유의점 |
|---|---|---|
| 대량 요청 불안정 | 응답 객체에 번역 선택지가 없는 상태가 발생 | 요청 전 간단한 실제 중국어 문장으로 응답 형식을 검증한다. |
| 표식 형식 불일치 | 장문 파일에서 줄 번호 표식의 순서가 맞지 않음 | 대형 원문은 문단 단위로 더 잘게 나누고 출력 복원 검사를 둔다. |
| 잔여 중국어 | 성공 처리된 파일도 중국식 인용부호·구두점·일부 이름이 남음 | CJK 전체 일괄 제거가 아니라 고유명사·문법 기호를 분리하여 후검수한다. |
| 외부 대안 | 키 없는 공개 경로 및 로컬 중계 번역은 품질/안정성 기준을 충족하지 못함 | 사용자 동의 없는 저품질 기계번역 결과를 적용하지 않는다. |

> **금지:** 오류를 피하려고 줄 전체를 기계적으로 치환하거나, 코드 문자열·정규식·YAML/JSON 키를 자연어처럼 번역하지 않는다.

## 5. `TRANSLATION_TODO.md`에서 따라야 할 핵심 규칙

다음 세션은 반드시 프로젝트 루트의 `TRANSLATION_TODO.md`를 원문 UTF-8로 다시 읽어 세부 파일명 표와 우선순위를 복구한다. 이번 확인에서 특히 중요한 규칙은 다음과 같다.

1. 중국어 **파일명·디렉터리명 변경은 `git mv` 또는 삭제+생성으로 Git 추적을 유지**한다.
2. `demo/`는 **본문을 건드리지 않고 이름만 변경**한다는 제약이 명시돼 있다.
3. `genre-prose-cards`의 두 폴더는 완전 동일한 복사본이므로 한쪽을 번역하면 다른 쪽에도 같은 변경을 반영한다.
4. 작업 순서는 번역 후 루트 전체에서 중국어 파일명 참조를 검색하고, 참조 경로도 업데이트하며, 마지막에 검증하는 방식이 권장돼 있다.
5. 본 문서가 아니라 `TRANSLATION_TODO.md`의 상세 표가 파일명 변경 대상과 표기 기준의 최종 근거다.
