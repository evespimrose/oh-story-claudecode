# 중한 번역 로컬라이제이션

중국어 프로젝트 문서를 단어 대 단어로 옮기지 말고, 문맥과 장르 기능을 보존한 자연스러운 한국어로 재구성한다. 번역 대상은 일반 문서 본문·주석·설명·예시이며, 실행에 연결된 문자열은 번역 대상에서 분리한다.

## 1. 시작 전 범위 확인

먼저 프로젝트 루트의 `AGENTS.md`와 `TRANSLATION_TODO.md`를 읽는다. `TRANSLATION_TODO.md`의 현재 재개 지점, 파일별 규칙, 완료 표시를 최우선으로 따른다. `git status --short`와 `git diff --stat`으로 작업 트리를 기록하고, 기존 사용자 변경을 복원·리셋·강제 체크아웃하지 않는다.

`demo/` 하위 본문을 수정하지 말라는 규칙이 있으면 본문 번역을 즉시 중단하고 파일명·디렉터리명 작업만 수행한다. 이미 규칙을 위반한 기존 변경이 발견되면 유지·복원 여부를 임의로 결정하지 말고 사용자에게 확인한다.

## 2. 대상 파일 준비

`git ls-files -- <path>`로 실제 추적 경로를 확인한다. 대상 파일을 원문 기준으로 읽고, 파일이 이미 수정되어 있으면 원문과 작업 트리를 구분한다. 작은 배치부터 처리하며, 한 파일의 원문을 별도 작업 공간에 복사해 번역 후보를 만든다.

다음 항목은 보호 목록으로 먼저 식별한다.

| 보호 대상 | 처리 원칙 |
|---|---|
| 경로·파일명·디렉터리명 | 프로젝트의 실제 경로와 링크 대상은 변형하지 않는다. 이름 변경은 TODO 매핑과 Git 추적 규칙에 따른다. |
| 명령어·스크립트명·옵션 | 실행 가능한 표기와 인자 순서를 보존한다. |
| URL·API 필드·JSON/YAML 키·식별자 | 자연어처럼 번역하지 않는다. |
| 정규식·CSS 선택자·테스트 픽스처 | 기능 대상 문자열을 보존하고, 설명만 번역한다. |
| Markdown 구조 | 제목 계층, 목록 순서, 표 열 수, 인용, 링크 대상, 코드 블록 경계와 줄바꿈을 유지한다. |
| 변수·상태 플레이스홀더 | `{X}`, `{N}`, `{原因}` 같은 토큰의 의미와 표기를 임의로 바꾸지 않는다. |

## 3. 번역 원칙

중국어의 수동 표현과 긴 수식어를 한국어의 능동적이고 짧은 문장으로 재구성한다. `进行`, `关于`, `对于` 등을 기계적으로 옮기지 않는다. 중국 고유의 관용구는 한국어 독자가 같은 기능을 이해할 수 있는 표현으로 바꾸되, 원문의 정보·어조·규범적 강도는 삭제하지 않는다.

코드 블록 안에서도 사람이 읽는 설명 문장은 한국어로 옮길 수 있지만, 코드·경로·키·정규식·명령어·플레이스홀더는 보존한다. 기능 문자열과 설명이 한 줄에 섞여 있으면 기능 문자열을 먼저 고정한 뒤 설명만 번역한다.

## 4. 자동 번역과 수동 대체

자동 번역 경로를 사용할 때도 대량 요청 전에 짧은 실제 중국어 문장으로 응답 형식을 확인한다. 빈 응답, 토큰 누락, 줄 병합, 코드 토큰 변형이 발생하면 해당 후보를 적용하지 않는다. 장문은 문서 경계와 코드 블록을 기준으로 작은 구간으로 나눈다.

자동 경로가 크레딧 부족·빈 응답·출력 잘림으로 중단되면 원문을 기준으로 수동 번역한다. 실패한 후보를 그대로 재사용하지 말고, 각 구간을 직접 읽어 문단 단위로 번역한다. 수동 번역에서도 보호 목록과 Markdown 구조를 먼저 지킨다.

## 5. 검증 게이트

번역 후보를 적용하기 전에 다음 검사를 수행한다.

1. 원문과 번역본의 Markdown 제목·목록·표·인용·코드 블록 경계를 비교한다.
2. 인라인 코드, 링크 대상, 경로, 명령어, 정규식, 키, 식별자, 플레이스홀더의 누락·변형을 확인한다.
3. 일반 본문에 남은 중국어를 재검색한다. 보호된 기능 문자열과 고유명사는 예외 목록으로 분리하고, 설명 문장에 남은 중국어는 다시 번역한다.
4. `git diff --check`를 실행한다.
5. 번역 후 파일이 원문보다 비정상적으로 짧아졌거나 줄이 합쳐졌다면 적용하지 않고 원문에서 다시 시작한다.

검증이 끝난 파일만 작업 트리에 복사한다. `git status --short`에서 대상 파일과 기존 변경을 구분하고, 대상 파일 외의 변경은 임의로 건드리지 않는다.

## 6. TODO와 인수인계

파일 번역이 검증되면 `TRANSLATION_TODO.md`에서 해당 항목을 완료 처리하고, 다음 미완료 대상과 재개 절차를 갱신한다. 전수 검증이 끝나지 않았다면 전체 번역 완료라고 선언하지 않는다. 다음 세션을 위해 자동 실패 원인, 수동 전환 여부, 보호 문자열 검증 결과를 인수인계 문서에 기록한다.

## 7. 커밋과 푸시

사용자가 커밋·푸시를 명시한 경우에만 실행한다. 먼저 `git diff --check`, `git diff --stat`, `git status --short`를 확인하고, 번역 관련 변경과 무관한 사용자 변경이 섞여 있으면 파일 단위로 분리한다. 커밋 메시지는 배치 번호와 대상 문서를 포함한다. 커밋 후 `git status --short`, `git log -1 --oneline`, 원격 동기화 상태를 확인하고, 명시적으로 요청된 경우에만 `git push origin main`을 실행한다.

## 완료 보고 형식

완료 보고에는 번역한 파일, 적용한 규칙, 보호 문자열 검증 결과, `git diff --check` 결과, TODO의 다음 대상, 커밋 ID와 푸시 결과를 간결하게 포함한다. 커밋·푸시하지 않은 경우 그 사실을 분명히 적는다.
